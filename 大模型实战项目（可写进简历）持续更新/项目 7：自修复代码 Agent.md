## 一、项目概述

**码匠（CodeCraft）**是一个基于大语言模型的自修复代码 Agent。它接收自然语言需求或函数签名，自动生成 Python 代码，在隔离沙箱中运行 pytest 测试，根据失败信息分析错误根因，并迭代修复直到测试通过或达到最大轮次。最终输出经过质量检查（lint、复杂度、覆盖率）的可交付代码。

> 🎯 **核心闭环：**需求输入 → 代码生成 → 测试执行 → 错误分析 → 代码修复 →（循环）→ 质量检查 → 交付

项目基于单张 24G 显存 GPU 部署，使用 DeepSeek-Coder-7B 作为基座模型，LangGraph 编排多轮修复状态机，Docker 提供安全执行沙箱。

### 2.2 各模块职责

模块

职责

关键实现要点

**Orchestrator**

LangGraph 状态机编排

维护全局 State（代码、测试结果、错误日志、迭代次数）；定义节点间条件边；控制最大修复轮次（默认 5 轮）；记录每轮快照用于回溯

**CodeGenerator**

根据需求生成初始代码

构建 System Prompt（角色设定 + 输出格式约束 + 代码规范）；User Prompt 包含需求描述、函数签名、示例测试；解析模型输出中的代码块（```python）；写入临时工作目录

**TestRunner**

在沙箱中执行 pytest

将生成代码和测试文件挂载到 Docker 容器；执行 pytest --tb=short -q；捕获 stdout/stderr/退出码；超时控制（默认 30s）；解析 pytest 输出为结构化结果（通过数、失败数、失败用例及 traceback）

**ErrorAnalyzer**

分析测试失败根因

提取失败 traceback 中的错误类型、错误消息、出错行号；结合代码上下文（出错函数前后各 5 行）；调用模型生成错误诊断（根因分类：语法错误 / 逻辑错误 / 边界条件 / 类型错误 / 导入缺失）；输出结构化诊断 JSON

**RepairAgent**

根据诊断修复代码

输入：当前代码 + 错误诊断 + 失败测试用例 + 历史修复记录（防止重复同样修复）；Prompt 要求只输出修改后的完整函数/文件，不输出解释；解析并替换代码；写入新版本快照
