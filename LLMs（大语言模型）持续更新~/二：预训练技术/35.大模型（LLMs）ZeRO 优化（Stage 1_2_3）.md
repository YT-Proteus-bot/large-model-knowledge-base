# 35.大模型（LLMs）ZeRO 优化（Stage 1/2/3）

> 原文：https://lcnipys9u0xh.feishu.cn/wiki/RdlMwr6zHiurCIkdVS6c9aFDnUg

#### 1. 解释 ZeRO 的核心理念：通过分片消除数据并行中的内存冗余

在标准数据并行（Data Parallelism, DP）中，每张 GPU 持有完整的模型副本，包括参数（Parameters）、梯度（Gradients）和优化器状态（Optimizer States）。当模型参数量 ΨΨ 很大时，单卡显存无法容纳，但 DP 的通信开销相对较低，扩展性好。ZeRO（Zero Redundancy Optimizer）的核心理念是：在数据并行的基础上，将原本每张 GPU 中冗余存储的模型状态分片（Shard）到所有数据并行进程上，每个进程只保留一部分状态，需要时再通过高效的集合通信从其他进程“借用”。这样，每张 GPU 的显存占用不再随模型总参数量线性增长，而是随数据并行度（*Nd*）的增加而近似反比下降，从而打破 DP 的内存墙，使得仅用 DP 就能训练超大模型。

ZeRO 并不改变 DP 的计算方式：每个进程仍然处理不同的 micro-batch，独立完成前向和反向计算，只是所需的完整状态（参数、梯度等）是通过通信动态获得的。

---

#### 2. ZeRO‑1：划分优化器状态，内存能节省多少？

ZeRO-1 仅将优化器状态分片到数据并行组内的 *Nd* 个进程中。假设优化器为 Adam，每个参数需要存储：

- 一阶动量 m*m* (FP32)
- 二阶动量 v*v* (FP32)
- 参数 p*p* (FP16，但优化器需要 FP32 副本用于更新)

优化器状态总字节数约为 12Ψ（每个参数 12 字节 = FP32 参数副本 4B + FP32 *m* 4B + FP32 *v* 4B）。在标准 DP 中，每张卡都存储完整的 12Ψ 字节；在 ZeRO-1 中，这 12Ψ12Ψ 被均分到 *Nd* 张卡，每张卡仅需存储 12Ψ/Nd字节。此外，参数（FP16）和梯度（FP16）仍被完整存储，各 2Ψ 字节。

#### 3. ZeRO‑2：额外划分梯度，说明梯度 reduce‑scatter 的过程

ZeRO-2 在 ZeRO-1 的基础上，进一步将梯度也分片到 *Nd* 个进程中。每张卡仍然存储完整参数，但只负责更新一部分梯度（对应于其分片的优化器状态）。反向传播计算出所有参数的梯度后，不再执行 All-Reduce 将完整梯度同步给所有进程，而是使用 Reduce-Scatter 操作：每个进程将自己的梯度贡献规约到对应分片的进程上，最终每个进程只拥有自己所负责的那部分参数的聚合梯度，然后更新这部分参数和优化器状态。

梯度 Reduce-Scatter 过程：

1. 每个 GPU 反向计算出完整梯度（所有参数），但梯度还没有同步。
1. 将完整梯度在 DP 组内进行 Reduce-Scatter：对于每个参数分片（假设按参数展平后均匀切分），执行 reduce-scatter 通信，使得第 *i* 个 GPU 最终获得该分片的规约和（所有 GPU 的贡献之和）。
1. 通信结束后，每个 GPU 仅持有自己所管理那部分参数的梯度（其余部分被释放），然后利用该梯度更新对应的优化器状态和参数。

![image](../../../assets/K0fFdqqyLohDyxxLhd8cGZTfnwh/WypGb2VwBovw8wxuCRMcwa2mnTc.png)

内存节省：每个 GPU 不再存储完整梯度（2Ψ 字节），而是只存储自己分片的梯度，大小为 2Ψ/*Nd* 字节。结合 ZeRO-1 的优化器分片，总模型状态内存（参数+梯度+优化器）降至 2Ψ+2Ψ/Nd+12Ψ/Nd。当 *Nd* 较大时，显存主要由参数占用，因此 ZeRO-2 对中型模型效果显著，但对超大模型仍有参数冗余。

#### 4. ZeRO‑3：划分模型参数，前向/反向中如何通过 all‑gather 获取完整参数？

ZeRO-3 将模型参数也分片到 DP 组内，每张卡不再存储完整参数，只在需要时通过 All-Gather 通信从其他进程收集完整参数。

- 前向传播：某一层计算前，该层的参数分片分布在各个 GPU 上。当前 GPU 发起 All-Gather，收集该层的全部参数；收集完成后进行该层的前向计算；计算完毕后，立即释放非本地分片的参数，只保留自己的分片（以节省显存）。
- 反向传播：同样，在计算某一层的梯度时，需要该层的完整参数，再次执行 All-Gather 获取完整参数；然后计算梯度；梯度在反向过程中通过 Reduce-Scatter 分发到对应负责的 GPU 上（与 ZeRO-2 类似），每个 GPU 最终只有自己分片的梯度。

通过这种“动态获取、即时释放”的机制，每张 GPU 显存中的参数存储量从 2Ψ 字节降为 2Ψ/Nd字节，从而使得单卡显存几乎不限制模型总大小（只要一个分片能放下）。ZeRO-3 的每卡总模型状态内存为 (2Ψ+2Ψ+12Ψ)/Nd=16Ψ/Nd 字节，实现了完全的分片。

---

#### 5. 详细描述 ZeRO‑3 的一次前向传播中参数的收集与释放时序

假设模型有 *L* 层，数据并行度 *Nd*。ZeRO-3 的前向传播逐层进行，每层参数的 All-Gather 与计算交替，释放紧跟计算后。

反向传播类似，在计算每层梯度前再次 All-Gather 完整参数，计算完梯度后释放，同时梯度通过 Reduce-Scatter 归约到各 GPU 的分片。

这种精密的时序控制使得 ZeRO-3 在显存开销上接近模型规模除以 *Nd*，是训练超大规模模型的关键技术。

#### 6. ZeRO‑Offload：将优化器状态和计算卸载到 CPU，如何隐藏数据传输开销？

ZeRO-Offload 针对 GPU 显存不足的场景，将优化器状态（动量、方差等）和优化器更新计算卸载到 CPU 内存，GPU 只保留参数和梯度，并在需要时与 CPU 交换数据。为了隐藏 CPU 与 GPU 之间的数据传输延迟，采用流水线和异步传输技术。

具体机制：

- 在反向传播结束后，GPU 上的梯度通过 Reduce-Scatter 聚集到各 GPU 的本地梯度分片。
