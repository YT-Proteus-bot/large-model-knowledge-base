# 92.大模型（LLMs）重排序（Reranker）

> 原文：https://lcnipys9u0xh.feishu.cn/wiki/MdouwCwh3iP6HNkt4PZcw9CSnYb

#### 1. Reranker 在 RAG 流程中的位置和作用是什么？为什么不能只依赖初检索？

在 RAG 流程中的位置：

Reranker（重排序模型）位于 RAG 管道的检索阶段之后、生成阶段之前，是一个连接“粗筛”与“精读”的关键中间层。典型的 RAG 数据流是：

```
代码块
用户查询 → 初检索（粗筛）→ 候选文档集（Top N） → Reranker（精排）→ 精选文档集（Top K） → 提示组装 → LLM 生成
```

在这个流水中，初检索负责从海量文档库中快速、高召回地捞出一个较大的候选池（例如 50~200 个文档）；Reranker 则对这个候选池进行二次精细排序，从中挑出与查询最相关的少数文档（例如前 3~5 个）送入生成模型。

核心作用：

Reranker 的本质任务是弥补初检索模型在精细语义区分能力上的不足，从而在保证召回的前提下，最大化最终的准确率。它通过更强的模型和更复杂的交互计算，重新评估每个候选文档的真实相关性。

为什么不能只依赖初检索：

初检索（无论是稀疏的 BM25 还是稠密的向量检索）受限于其架构和效率要求，不得不做出精度上的妥协。

- 双塔模型的局限性：主流的稠密检索采用双塔结构，查询和文档在编码时完全独立，交互仅发生在最终向量的单点内积上。这种“浅交互”无法捕捉查询词与文档词之间的复杂关系（如否定、限定、词序、局部匹配等）。一个初筛模型可能因为文档整体语义相近而打出高分，却忽略了关键细节。例如，对于查询“不含咖啡因的咖啡”，初筛可能返回大量关于“咖啡的好处”的文档，因为它们在整体语义上相近，但忽略了“不含咖啡因”这一关键限定。
- 单向量表示的瓶颈：将长文档压缩为单个固定维度向量，会导致信息稀释，尤其会丢失关键实体的精确匹配信号。
- 效率和精度的取舍：初检索要求在毫秒级内从百万、亿级文档中完成搜索，因此必须使用高效的近似最近邻算法和较浅的编码器，这不可避免地牺牲了部分精度。

因此，Reranker 是 RAG 系统中以计算换精度的关键组件。它承接初检索的高召回，产出高精度，保证最终输入到 LLM 的上下文既相关又精炼，极大提升了答案质量和系统效率。

#### 1. 重排序模型通常采用什么架构？Cross-encoder 与 Bi-encoder 的核心区别。

重排序模型目前最主流的架构是 Cross-encoder（交叉编码器），它与初检索常用的 Bi-encoder（双塔编码器） 形成了鲜明的互补。

Bi-encoder（双塔模型）：

- 架构：拥有两个独立的编码器塔（或共享权重），分别对查询和文档进行编码，输出各自固定长度的向量。相关性分数通过计算两个向量的余弦相似度或内积得到。
- 工作方式：文档向量可以离线预先计算并建库，查询时只需实时编码查询向量，然后通过 ANN 快速搜索。查询和文档在编码过程中完全独立，没有交互。
- 特点：速度极快，适合大规模检索；但交互性弱，语义区分能力有限。

Cross-encoder（交叉编码器）：

- 架构：通常基于 BERT 等 Transformer 编码器，将查询和文档拼接成一个完整的序列输入：[CLS] query [SEP] document [SEP]。模型通过多层自注意力机制，让查询的每个 Token 与文档的每个 Token 进行充分的、全对全的交互。
- 工作方式：无法预先计算文档向量，必须在推理时为每一对 (query, document) 完整地运行一次前向传播，在 [CLS] 向量之上接一个线性分类头，输出一个相关性分数。
- 特点：精度极高，能捕捉复杂的语义匹配关系；但计算开销大，无法用于海量文档的初筛。

正是由于这种架构上的根本差异，才决定了 Cross-encoder 成为 Reranker 的首选。它用昂贵的实时计算，换取了 Bi-encoder 无法企及的排序精度。

#### 3. 为什么 Cross-encoder 排序更准确但计算开销更大？推理时的输入形式是什么？

为什么排序更准确：

Cross-encoder 的准确性优势源于其全交互的注意力机制。在 Bi-encoder 中，查询和文档的表示是在彼此“不知情”的情况下生成的，向量内积是唯一的信息交汇点。这是一种极度压缩的交互，会丢失大量细粒度匹配信号。而在 Cross-encoder 中，查询和文档被拼接送入同一个 Transformer 网络。自注意力机制让模型能够：

- 精确捕捉局部匹配：查询词“苹果”可以直接注意到文档中的“iPhone”，理解二者在当前上下文中的关联。
- 理解词序和限定关系：对于“除了苹果之外的水果”，模型能通过注意力关注到“除了”这个否定词，以及它与“苹果”的关系，从而避免错误匹配。
- 建模复杂的句法结构：模型可以学习到哪些查询词对应文档中的哪些片段，以及它们之间是因果关系、并列关系还是转折关系。
- 动态评估相关性：不同于提前压缩的固定向量，Cross-encoder 可以根据查询的不同，动态地关注文档中不同的部分，实现“定制化”的相关性评估。

这种深度、上下文相关的交互，使得 Cross-encoder 在判断相关性时，更像一个“阅读理解”模型，而非简单的“向量对比”。

为什么计算开销更大：

开销大的根本原因在于无法预计算。对于每一个查询，Reranker 必须将它与每一个候选文档分别拼接，然后完整地执行一次 Transformer 前向传播。这个计算成本与候选文档数量成正比。而 Bi-encoder 的文档向量是离线计算好的，在线只需一次查询编码和快速的内积运算。

推理时的输入形式：

典型的输入格式如下（以 BERT 架构为例）

```
代码块
[CLS] 查询文本 [SEP] 文档文本 [SEP]
```

- [CLS]：这是 BERT 预留的用于分类任务的聚合 Token。经过多层 Transformer 处理后，其对应的最终隐藏状态向量会被送入一个单层线性分类器，输出一个标量作为相关性分数。
- [SEP]：用于分隔查询和文档，帮助模型区分两个不同的文本段。
- 输入的文本通常会进行截断，以符合模型的最大长度限制（如 512 Token）。优先保留查询的完整性，并在必要时截断文档的尾部。

整个流程就是：对每一对 (query, doc)，构造这样一个序列，送入模型，取 [CLS] 输出，计算得分，然后对所有候选文档按得分降序排列。
