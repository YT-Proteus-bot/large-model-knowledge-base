# 88.大模型（LLMs）表格与多模态文档处理

> 原文：https://lcnipys9u0xh.feishu.cn/wiki/FXgmws02nis5pvkd25rcgWzCnbb

#### 1. 为什么表格数据对传统 RAG 构成挑战？直接用文本表示表格会丢失哪些信息？

表格是人类表达结构化信息最密集的形式之一。它之所以对传统 RAG 构成巨大挑战，是因为 RAG 的核心——文本嵌入模型和生成模型——都是为处理线性、连续的叙事文本而设计的，而表格的本质是二维的、关系型的、视觉导向的。

直接将表格“拍平”成纯文本，会丢失三个层次的关键信息：

- 空间与结构信息：表格的行列对齐、单元格的视觉分组，是帮助人类快速理解数据归属关系的核心线索。当表格被线性化为一串文本时，“北京”和“100万”之间的行列关联就变成了靠逗号或空格分隔的两个词，模型必须从零推断它们的关系，这增加了认知负担，也容易出错。这种平面结构的丧失，是信息丢失中最根本的一种。
- 层级与语义关系：真实世界的表格远不止简单的二维网格。多层表头会构成“大类-小类”的层次分类体系；合并单元格则承载着“一个值跨越多个子类别”的语义。这些复杂的层级信息在纯文本流中几乎不可能被完好地表达，模型只能看到一个被拉平后的字符串，无法还原其内部的语义层级。
- 数值的物理意义与可比性：表格中大量的数字并非孤立，它们有着特定的单位、量纲和物理意义。它们共同表达着一种对比、趋势或分布关系。例如，一个销售表的核心是“各产品在不同地区的销售额对比”。文本化后，数字和表头分离，模型需要先艰难地重建数字与语义的绑定关系，才能进行推理和比较，这个过程极容易产生幻觉。

因此，简单的文本表示会让表格从“高度结构化的知识库”退化为“一堆有关联但难以解析的文本片段”，使得 RAG 系统的检索和生成两个环节都受到严重损害。

#### 2. 有哪些表格序列化方式（CSV、Markdown 表格、JSON、HTML），哪种对 LLM 最友好？为什么？

常见的表格序列化格式主要有 CSV、Markdown 表格、JSON、HTML 四种。它们对 LLM 的友好程度，取决于其结构开销、语义清晰度以及模型训练数据中的出现频率。

> （此处为内嵌电子表格，需登录飞书查看）

Markdown 表格胜出的根本原因：

- 训练数据的亲和性：LLM 的训练语料（特别是代码和技术文档）中包含了海量的 Markdown 表格，这使得模型对这种格式的理解最为自然和精准。
- 结构直觉化：Markdown 表格使用 | 分隔列，用 --- 分隔表头和数据，这种视觉化的结构接近于人类阅读表格的习惯，模型能轻易地将文本表示与二维布局关联起来。
- Token 效率：相比 HTML 和 JSON，Markdown 表格的 Token 开销极低。在 LLM 的上下文窗口中，这一点至关重要。

最佳实践：对于绝大多数 RAG 场景，应首选 Markdown 表格。如果遇到 Markdown 无法表达的复杂合并单元格，可以在 Markdown 表格内部或旁边，用自然语言显式地补充说明这种合并关系，例如在表头添加注释。

#### 3. 如何从图像或 PDF 中精确提取表格结构（单元格位置、合并单元格、行列关系）？

从非结构化文档中精确提取表格结构，是一个从“看见”到“理解”的过程，需要专门的技术。传统方法依赖视觉线条，而现代方法则转向基于语义的端到端模型。

传统计算机视觉方法：

这种方法分三步：检测表格区域、识别行列线和分析结构。它依赖图像中的水平与垂直线条来定位单元格，适用于线条清晰、格式规整的表格。但局限性极强：对于无线条表格、仅靠色块区分行列的表格，或者线条断裂、弯曲的扫描件，几乎完全失效。

现代深度学习模型方法：

这是目前工业界的主流，直接在图像上预测表格的逻辑结构，不再依赖于物理线条。其代表模型如百度的 SLANet、Google 的 Table Transformer、微软的 TableNet 等。它们能够同时完成两个任务：检测出每个单元格的精确位置；并推断出任意两个单元格之间是否存在“同一行/同一列”的逻辑关系。因此，即使表格没有线条，模型也能根据文本的对齐规律重建其行列结构。对于合并单元格，模型通常会预测单元格的起始行/列和跨行/列的数量，从而完整记录其合并信息。

处理流程：

1. 使用表格检测模型从文档图像中定位出所有表格的边界框。
1. 将每个表格区域裁剪并送入表格结构识别模型。
1. 结构识别模型输出每个单元格的坐标、内容以及它的行列逻辑关系（如 rowspan=2, colspan=3）。
1. 将逻辑结构转换为 Markdown、HTML 或 JSON。

对于 PDF 文件，可以先用 PyMuPDF 获取页面上每个文本片段的精确坐标和字体信息，然后利用这些坐标信息辅助模型判断单元格归属，这比单纯基于图像的识别更为精准。

#### 4. 对于复杂表格（多层表头、跨行跨列），转换为文本后应如何描述以保持语义？

复杂表格的语义在于其层级结构和数据归属关系。转换为文本时，如果强行将其拍平，必然导致信息丢失。更好的策略是进行“语义增强”或“逻辑拆分”。

策略一：转换为结构化 Markdown + 显式注释。
在 Markdown 表格中，使用空行、缩进或特殊符号来模拟层级。例如，一个有两层表头的表格，可以将第一层表头作为一个合并后的分组标题，用类似 Markdown 注释的方式在表前显式声明合并关系。例如：“（注：以下表格中，‘2023年’为跨‘Q1-Q4’的表头）”。然后在表格体内部，通过重复或缩进等方式来保持可读性。这种方式的优点是保留了表格的整体性，LLM 对 Markdown 的理解较好。

策略二：拆分为多个规范子表。

将一个复杂的多层级表格，依据其顶层分类，拆解为多个扁平、独立的三范式表格。每个子表只含单层表头，表名则包含了其完整的层级路径。例如，原表为“销售数据 > 2023年 > Q1/Q2/Q3/Q4”，可以拆分为：

- “销售数据_2023年_Q1”
- “销售数据_2023年_Q2”
- ...
  每个子表都是简单的行列结构。这种方式最干净，能最大化地利用向量嵌入和检索的效率，但拆解后需要在外部的索引元数据中维持它们之间的关联。

策略三：自然语言描述 + 表格内容。

将表格的复杂结构信息，用一段精炼的自然语言文本显式地描述出来，然后将这段描述作为该表格块的“元数据”或“前导文本”一起嵌入。例如：“该表格是一个两层表头结构，第一层表头为‘2023年’和‘2024年’，分别跨越四列。2023年下又分为Q1-Q4四个季度。” 随后再附上拍平后的数据。这样，即使表格数据本身丢失了层级，前导文本也能为 LLM 提供清晰的解读钥匙。

在实践中，策略一和策略三常常结合使用，能够最大程度地保留复杂表格的语义完整性。

#### 5. 表格表示与 embedding：能否直接对表格生成向量？有哪些专用的表格嵌入模型？

可以直接对表格生成向量，而且效果远超简单的文本拍平。专用的表格嵌入模型通过设计特殊的输入结构和预训练任务，能够编码表格的结构、文本和数值等多维信息。

专用表格嵌入模型：

- TAPAS (Table Parser)：Google 提出的经典模型。它会在输入文本中添加特殊的 Segment Embeddings 来区分表头、数据单元格和位置信息（如行/列 ID），使模型能直接感知表格的二维结构。TAPAS 常用于先检索相关表格，再进行答案抽取，但它本身不直接输出句向量。
