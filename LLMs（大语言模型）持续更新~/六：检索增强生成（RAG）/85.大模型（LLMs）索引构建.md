# 85.大模型（LLMs）索引构建

> 原文：https://lcnipys9u0xh.feishu.cn/wiki/SkhxwrnkSi7qcRkf8LOcNILdnr0

#### 1. 什么是 RAG 中的索引？索引的构建在整个 RAG 流程中处于什么位置，起什么作用？

在 RAG（检索增强生成）系统中，索引是指将外部知识库中的文档或数据，预先处理并组织成一个可高效检索的数据结构的过程及其最终产物。这个索引不是简单的目录，而是一个将非结构化的自然语言文本，转化为机器可计算、可快速比对相似度的数学表示（通常是向量），再辅以元数据标签的复杂信息仓库。

索引的构建位于 RAG 流程的离线阶段，也就是在用户查询到来之前就已经完成。它处于整个流水线的最上游，与在线阶段的“查询-检索-生成”形成清晰的时序分离。在离线阶段，我们投入计算资源对文档进行解析、分块、嵌入，并存入索引库；在线阶段，用户的查询被实时嵌入后，通过索引快速检索出最相关的文本块，作为生成模型的上下文。

索引在 RAG 中发挥着三大核心作用：

1. 知识的物理载体：它将 LLM 的参数化记忆之外的外部知识，以一种结构化、可持久化的方式保存下来。这使得模型可以访问到训练截止日期之后的信息、企业内部文档或任何特定领域的私有数据。
1. 检索效率的倍增器：面对海量文档，逐字比对是不可能的。索引，特别是向量索引，通过近似最近邻（ANN）搜索算法，将检索时间从与文档总量线性相关的 O(N)，降低到亚线性甚至对数级别，使毫秒级的语义搜索成为可能。
1. 语义匹配的桥梁：通过嵌入模型，索引将“意思相近”的文本映射到向量空间中邻近的位置。这使得用户可以基于意图而非仅仅关键词来检索信息，这是传统关键词索引无法做到的。它让检索从“字面匹配”升级为“意图理解”。

因此，RAG 系统的性能上限，很大程度上取决于索引的质量。一个构建粗糙、信息丢失或检索效率低下的索引，会导致后续生成步骤“垃圾进，垃圾出”，使整个 RAG 系统失效。

#### 2. 构建索引的典型步骤有哪些？从原始文档到可查询的向量/关键词库，画出简要流水线。

从原始文档到可查询的索引库，是一个典型的离线数据处理管道，主要包括以下步骤：

步骤1：数据摄取与解析

首先从各种异构数据源（如PDF、网页、数据库、Word文档等）中读取原始文档。解析器的任务是将这些格式各异的文件，转化为统一的、干净的纯文本，同时尽可能地保留有用的结构信息（如标题、表格）。

步骤2：文本分块

将长文档分割成大小合适的文本片段或“块”。这是至关重要的一步，因为嵌入模型通常有最大输入长度限制（如512或8192个Token），且太长的文本会稀释语义焦点，导致检索不准。分块策略需兼顾语义完整性（让一个块尽量包含一个完整的意思）和检索效率。常见的方法有固定长度分块、基于标点或段落的分块、以及使用专门的分块模型进行语义分块。

步骤3：嵌入与向量化

将每一个文本块送入一个文本嵌入模型，将其压缩映射为一个固定维度的稠密向量。这个向量就是该文本块在语义空间中的坐标。优秀的嵌入模型能确保语义相似的文本拥有相近的向量表示。

步骤4：元数据提取与标注

为每个文本块提取并存储关键的元数据，例如：来源文档名、作者、创建日期、页码、标题层级等。这些元数据不会直接参与向量相似度计算，但对检索后的过滤和溯源至关重要。

步骤5：构建索引并持久化

将生成的向量、原始文本和元数据，一并写入到索引存储中。对于向量部分，索引系统会构建特定的数据结构以实现高效的 ANN 搜索。最后将整个索引持久化到磁盘，供在线服务加载使用。

简要流水线图：

```
代码块
[原始文档 (PDF, HTML, ...)]
    -> (1. 解析器)
    -> [纯文本]
    -> (2. 文本分块器)
    -> [文本块列表]
    -> (3. 嵌入模型)
    -> [向量列表] + [元数据]
    -> (4. 索引构建器)
    -> [可查询的向量索引库]
```

#### 3. 为什么多数 RAG 系统选择向量数据库作为索引存储？向量索引与传统倒排索引有何本质区别？

多数 RAG 系统选择向量数据库作为核心索引存储，是因为 RAG 的检索目标本质上是一个语义相似度搜索问题，而这正是向量索引的专长。它能捕捉用户查询背后的意图，而不是机械地匹配文本字符串。

向量索引与传统倒排索引的本质区别：

- 匹配逻辑不同：倒排索引（如 Elasticsearch 的 BM25）是基于字面或词频统计的，它建立一个从“关键词”到“文档ID列表”的映射。检索时，只有当查询中的词与文档中的词精确匹配（或经词干化、同义词处理后匹配）时，文档才会被命中。向量索引则不同，它通过嵌入模型将文本映射到高维向量空间，基于向量间的距离（如余弦相似度、欧氏距离）来衡量语义相似度。即使查询和文档用词完全不同，只要意思相近，它们的向量距离依然很近。这解决了传统检索中的“词汇鸿沟”问题。
- 索引结构不同：倒排索引的核心数据结构是 Posting List（倒排列表），结构相对简单，对精确匹配和简单逻辑组合的效率极高。向量索引的核心则是为了加速在高维空间中查找最近邻而设计的复杂图或树结构（如 HNSW、IVF），其目标是解决高维空间中的“维度灾难”，实现快速的近似搜索。
- 对数据的表示不同：倒排索引直接存储和索引词项，信息是可解释的。向量索引存储的是由模型生成的抽象向量，这个向量本身对人类不可读，是对文本深层语义的压缩编码。

向量数据库的附加优势：现代向量数据库（如 Milvus、Pinecone）不仅仅是一个向量搜索引擎，它们往往同时集成了标量过滤（基于元数据）和向量搜索的能力，并能在一个查询中混合使用。它们还专门针对向量数据的大规模存储、内存管理、增量插入和分布式扩展进行了深度优化，这些都是传统全文搜索引擎所不擅长的。因此，选择向量数据库是在语义匹配能力、检索效率和系统工程化之间取得的最佳平衡。

#### 4. 解释向量索引中的近似最近邻（ANN）搜索原理，列出至少三种主流 ANN 算法。

在高维向量空间中进行精确的最近邻搜索，计算成本会随数据规模N线性增长，即 O(N*d) 的复杂度，这在百万、亿级规模下是完全不可接受的。近似最近邻（ANN）搜索的核心思想就是牺牲少量可接受的精度，换取检索速度的大幅提升。它不再保证返回的一定是距离最近的 K 个点，而是允许返回与最近邻非常接近的结果，从而将复杂度降低到亚线性甚至对数级别。

ANN 算法通过预先构建一个精巧的索引结构，来缩小搜索时需要计算距离的候选向量范围。查询时，算法根据索引结构快速地定位到可能包含最近邻的一个小范围子空间，然后仅对这个小范围内的向量进行精确距离计算和排序。

三种主流 ANN 算法：

1. 基于图的算法 - HNSW：
   这是目前综合性能最出色的算法之一。它构建一个分层可导航小世界图。索引时，向量被插入到不同层级的图中，每层都是一个近邻图，上层节点稀疏，下层节点稠密。搜索时，从最顶层的稀疏图开始，快速跳跃到一个靠近目标的区域，然后逐层向下，在越来越稠密的图中精细搜索。就像在导航中先走高速公路接近目的地，再进入城市小路精确到达。

1. 基于聚类的算法 - IVF (Inverted File Index) 及其变体 (IVF_FLAT, IVF_PQ)：
   它首先将全量向量通过 K-Means 等算法聚为若干个簇。索引结构本质上是一个“倒排表”，记录了每个簇中心及其包含的所有向量。查询时，不需要计算与所有向量的距离，只需先找到距离查询向量最近的几个簇，然后暴力搜索这几个簇内部的向量。IVF_PQ 变体还会在簇内部对向量进行乘积量化（PQ）压缩，进一步降低内存占用和计算量。

1. 基于树的算法 - Annoy (Approximate Nearest Neighbors Oh Yeah)：
   Spotify 开源的算法。它通过构建多棵随机二叉树来将向量空间不断二分割。每棵树都是随机选择两个点做超平面，将空间一分为二，不断递归，直到每个叶子节点只包含少量向量。查询时，遍历每棵树，定位到目标向量所在的叶子节点，并将这些叶子节点中的所有向量作为候选集进行精确排序。它通过增加树的棵数来提高搜索精度。

1. 基于量化的算法 - ScaNN (Scalable Nearest Neighbors)：
   Google 开发的算法，其核心是通过创新的各向异性向量量化技术，优化了内积搜索的性能。它在压缩向量的同时，特别关注高相似度区域的分辨率，在极高压缩比和极低延迟的场景下表现卓越。

#### 5. HNSW 索引的层次图结构是如何加速相似性搜索的？它的插入、查询复杂度是多少？

HNSW 的加速原理可以类比于高速公路与城市道路的层级递进，它通过构建一个层次化的、可导航的小世界图，让搜索过程既能进行大范围的快速跳跃，又能进行局部的精细探索。
