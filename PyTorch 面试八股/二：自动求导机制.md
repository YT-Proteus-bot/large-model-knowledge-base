#### 1. PyTorch动态计算图是如何构建和释放的？

PyTorch 采用动态计算图（Define-by-Run）机制，计算图在每次前向传播时动态构建，在反向传播完成后立即释放。

构建过程：

- 当你对一个设置了 requires_grad=True 的张量执行操作（如 +, *, mm 等），PyTorch 会创建一个对应的 Function 对象，记录该操作的输入、输出以及反向传播所需的梯度计算逻辑。
- 这个 Function 对象被链接到输入和输出的 Tensor 上，形成一条有向无环图（DAG）。图中的节点是张量（数据）和 Function（操作），边表示数据流向。
- 每执行一个新操作，计算图就动态增长。因为是动态的，所以图可以随 Python 控制流（如 if-else, for 循环）变化而改变形状，非常灵活。

释放过程：

- 当调用 .backward() 时，自动求导引擎沿着计算图反向遍历，依次计算每个 Function 的梯度，并将梯度写入参与的张量的 .grad 属性中。
- 反向传播完成后，中间张量（非叶子节点）的梯度以及部分计算图结构通常会被释放，以节省内存。这也是为什么多次调用 .backward() 时，若不设置 retain_graph=True，图会被销毁而无法再次反向传播。

叶子节点：直接由用户创建的、没有历史操作的张量（如 w = torch.randn(3, requires_grad=True)）是叶子节点。计算图的“输入”通常是叶子节点，它们的梯度在反向传播后被保留在 .grad 中，用于优化器更新。

#### 2. requires_grad=True 在计算图中起什么作用？

requires_grad 是张量的一个属性，它决定了该张量是否需要被追踪梯度，以及是否参与计算图的构建。

- 当一个张量的 requires_grad=True 时，所有依赖它的操作所产生的新张量都会自动具有 requires_grad=True（除非显式指定为 False），并且这些操作都会被注册到计算图中。
- 在反向传播时，只有 requires_grad=True 的叶子张量才会被计算并累积梯度（存入 .grad）。
- 它相当于告诉 PyTorch：“我希望优化这个张量，请记录所有依赖于它的计算，以便后续自动求导。”

实用场景：

- 模型参数：nn.Parameter 内部将张量的 requires_grad 自动设为 True，因此所有模型参数默认需要梯度。
- 冻结部分网络：在微调时，将某些层设置为 requires_grad=False，可以冻结这些层，只更新其余部分，既节省显存又防止遗忘。
- 输入数据：通常将输入数据的 requires_grad 保持为 False，因为不需要优化输入，这也能避免构建不必要的计算图。

#### 3. backward() 函数调用后具体计算了哪些梯度？

backward() 是自动求导引擎的入口。当调用 loss.backward() 时，引擎会执行以下步骤：

1. 从 loss 张量开始，沿着计算图反向遍历所有 Function 节点。
1. 对于每一个 Function，调用其预定义的 backward() 方法，利用链式法则计算该操作的输入梯度。
1. 将这些输入梯度传播到更早的节点，并累加到这些节点的 .grad 属性中。
1. 最终，所有 requires_grad=True 的叶子张量都会得到一个 .grad，其值等于损失函数对该叶子张量的梯度。

注意：

- backward() 默认只对标量损失工作。如果要对非标量张量调用 backward()，必须提供一个与调用张量形状相同的 gradient 参数，作为外部梯度。
- 中间张量（非叶子）的梯度通常被自动释放，除非特别指定 retain_grad()。

---

#### 4. 如何只计算部分张量的梯度而忽略其他？

可以通过设置张量的 requires_grad 属性来控制。

- 在创建张量时：x = torch.randn(3, requires_grad=False)。
- 对已有张量：x.requires_grad_(False)（就地操作）或 x = x.detach()（创建一个共享数据但不需要梯度的新张量）。
- 在上下文管理器中临时禁用：使用 torch.no_grad() 包裹代码块。在此块内的所有操作都不会构建计算图，即使输入张量 requires_grad=True。这在模型评估或推理时非常有用，能显著减少显存占用和计算开销。

微调示例：冻结预训练模型的卷积层，只训练最后的分类头。

```
代码块
for param in model.backbone.parameters():
    param.requires_grad = False

# 之后只有分类头的参数会接收梯度更新
```

#### 5. 叶子节点和非叶子节点在梯度保留上有何区别？

- 叶子节点：直接由用户创建的、没有 grad_fn 的张量（例如 nn.Parameter 或 torch.randn(..., requires_grad=True)）。当反向传播完成后，它们的梯度被保留在 .grad 属性中，这是优化器更新参数的基础。
- 非叶子节点：计算图中的中间结果，例如 y = x * 2 中的 y。默认情况下，反向传播完成后，非叶子节点的梯度会被立即释放，以节省内存。
