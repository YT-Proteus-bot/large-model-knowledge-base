#### 1. TorchScript是什么？trace和script两种方式有何区别？

TorchScript 是PyTorch模型的一种中间表示（IR），它允许将PyTorch模型（通常定义在 nn.Module 中）序列化为一个可优化、可独立于Python运行的文件。它的核心目的是部署：将模型从需要Python环境的动态图，转换为一个静态的、可被高性能推理引擎（如LibTorch、ONNX Runtime、TensorRT）执行的格式。TorchScript模型不再依赖Python解释器，因此可以在C++环境、移动端或生产服务器上高效运行。

PyTorch提供了两种将模型转换为TorchScript的方法：torch.jit.trace 和 torch.jit.script。它们的工作机制和适用场景截然不同。

> （此处为内嵌电子表格，需登录飞书查看）

核心区别：

- trace 是一个“观察者”，它给定一个样例输入，运行一次模型，并将执行的操作记录下来，形成一个静态计算图。它无法记录未被触发的分支，因此对于控制流（如 if x > threshold: ... else: ...），它只会记录实际执行的那条路径。
- script 是一个“编译器”，它直接阅读你的Python代码（通过 torch.jit.script 装饰器或函数调用），将其翻译为TorchScript IR。它不需要运行模型就能理解控制流，因此可以处理动态结构。

应用场景选择：

- 如果模型是标准的CNN、Transformer等，且没有依赖数据的复杂分支，使用 trace 即可，更简单快捷。
- 如果模型包含动态循环（如基于序列长度的RNN）、条件判断（如mask操作中的 if）、或自定义的复杂逻辑，则必须使用 script。

#### 2. 如何使用torch.jit.trace将模型转为TorchScript？有什么限制？

使用 torch.jit.trace 将模型转为TorchScript的基本步骤如下：

```
代码块
import torch
import torch.nn as nn
class MyModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(10, 10)
    def forward(self, x):
        return self.linear(x)
model = MyModel()
model.eval()

# 准备一个样例输入，形状需要与实际输入匹配
example_input = torch.randn(1, 10)
traced_model = torch.jit.trace(model, example_input)

# 保存
traced_model.save("traced_model.pt")
```

trace 的限制：

1. 不支持数据依赖的控制流。trace 只记录实际执行的操作路径。如果模型中有 if x.sum() > 0: ... else: ...，trace 只会固化在追踪时走的那条分支。如果之后输入改变，本应走另一条分支，但TorchScript模型仍然执行原来那条路径，导致错误。这是 trace 最大的缺陷。
1. 输入形状被部分固定。trace 记录的是特定输入形状下的张量操作。虽然可以通过动态轴（如 torch.jit.trace 后使用 torch.jit.freeze 等）来处理变化，但追踪时确定的某些维度可能无法自动泛化到任意大小。通常，只要模型中没有根据输入形状动态改变网络结构（如动态循环），trace 能正确处理不同batch size（通过将输入的第0维设为动态，见后续ONNX导出中的动态轴）。
1. 无法处理 torch.Tensor 的元组或列表的不规则构造。如果 forward 返回一个动态长度的列表，trace 可能失败。
1. 不能包含非PyTorch的Python操作，例如 print、文件I/O等，这些在 trace 时会被忽略或导致错误。

克服限制：对于控制流，可以使用 torch.jit.script。对于动态形状，trace 本身并不固定batch维，只要在推理时传入不同batch大小的输入，即可正常工作，因为线性层等操作对batch维是透明的。但若模型中有 view 或 reshape 依赖于输入的具体值，可能会导致问题，此时需要谨慎处理。

#### 3. torch.jit.script适合什么类型的模型？为什么比trace更通用？

torch.jit.script 适合包含动态控制流、复杂数据结构、依赖数据的逻辑判断的模型。例如：

- 自然语言处理中的RNN/LSTM，其循环次数依赖于输入序列长度。
- 基于注意力机制的模型，其中可能存在根据注意力权重进行的动态mask或条件分支。
- 任何包含 if, while, for 等Python控制流，并且这些控制流依赖于张量数值的模型。
- 使用了递归或树结构的模型（如Tree-LSTM）。

为什么比trace更通用？
script 直接解析Python源代码的抽象语法树（AST），将其编译为TorchScript的中间表示。它不依赖于实际运行一次样例输入，因此能够完整地保留模型定义中的所有逻辑，包括所有可能的分支和循环。script 从根本上解决了 trace 无法处理数据依赖控制流的问题。只要代码语法被TorchScript支持（大部分Python子集），script 就能将其忠实地转换为静态图。
