# 你的 Agent 项目里，Redis 内存淘汰策略选的是什么？为什么在记忆场景下不能用默认的 noeviction？

> 主题：AI Agent+后端精选八股文 › Cache & DataBase篇/Redis/分布式锁　｜　原始文件：AI Agent+后端精选八股文/Cache & DataBase篇/Redis/分布式锁/你的 Agent 项目里，Redis 内存淘汰策略选的是什么？为什么在记忆场景下不能用默认的 n.md

“记忆场景如果用默认的 noeviction，几乎等于给 Agent 埋了颗定时炸弹。Agent 的记忆写入是持续不断的——会话上下文、Skill 缓存、向量索引，每秒钟都在往里塞新数据。一旦内存满了，noeviction 会让所有新的写入直接报错，任务中断、对话丢失，用户立刻感知到故障。这就像给一个不停进货的仓库规定了‘满了不准扔东西也不准进货’，仓库早晚会撑爆，而不是平稳运行。

我们在选型时，核心思路是：用分层淘汰代替全局硬抗，让 Redis 自己学会清理不那么重要的数据，而不是等满了再崩溃。

我们的选择策略分三类数据：

1. 会话级短期记忆：volatile-lru 或 allkeys-lru

短期记忆比如 session:abc123:messages 对话历史、session:abc123:state 当前状态。这类数据读写频繁，但生命周期很短（通常 TTL 30 分钟），且一旦会话结束就可以丢弃。我们会在 Redis 实例上开启 volatile-lru 策略，只淘汰设置了过期时间的键。这样即便内存紧张，也是踢掉那些已经闲置较久的短期记忆，而不是杀掉正在活跃的会话。如果整个实例里短期记忆占比极大，也会用 allkeys-lru，因为基本所有键都设了 TTL，不存在误杀永久数据的问题。LRU 算法天然适合对话场景——越久没说话的会话，越可能已经断了。

1. 长期记忆和用户画像：noeviction，但放在独立实例且严格控制

用户偏好、历史决策这些长期记忆绝不能因为内存不够就被悄悄淘汰，丢失了等于 Agent 失忆。所以这部分数据我们放在独立的 Redis 实例里，策略设为 noeviction。但光设 noeviction 不安全，我们还配合：

- 容量预估与扩容告警：根据用户量估算记忆数据大小，提前扩容，设内存上限并监控使用率，到 80% 就告警。
- 严格的数据治理：不是所有东西都算长期记忆，只有经过提炼和重要性评分的才存进去，垃圾数据不进这个实例。
- 归档机制：极老的记忆（比如超过 90 天未访问）异步迁移到廉价存储（如对象存储），保持 Redis 里是热温数据。
1. 向量索引：noeviction + 冗余副本

向量索引的内存占用大而且不可压缩，淘汰一条文档会导致索引质量下降。我们也用独立实例 + noeviction，但接受一个事实：万一真的满到爆，宁可牺牲部分查询，也不能让写索引失败导致文档丢失。所以我们会维护一个只读副本用于查询，主节点写满前强制做分片扩容。

为什么不能用默认的 noeviction？一句话总结：Agent 的记忆天生是无限的，但 Redis 的内存是有限的。用 noeviction 是让有限去硬扛无限，必死；用合适的淘汰策略是让 Redis 学会按规则遗忘，让系统优雅地活下去。

## 淘汰策略决策图（文本）

```
Agent Redis 数据分层
├── 会话短期记忆 (有 TTL, 可丢)
│   └── 策略: volatile-lru 或 allkeys-lru
│         └── 只淘汰闲置会话，活跃会话不受影响
│
├── 长期记忆/用户画像 (不可丢)
│   └── 策略: noeviction + 独立实例
│         ├── 容量监控 + 告警自动扩容
│         └── 冷数据归档，控制热数据体量
│
└── 向量索引 (体积大, 不可丢)
    └── 策略: noeviction + 分片 + 副本
          └── 写满前扩容，查询走副本保可用
```

## 策略对比速记表

> 〔原文此处为飞书内嵌组件，内容未随导出〕

一个线上教训：我们最开始偷懒，所有 Agent 数据共用一个 Redis，设了 noeviction。结果一次流量小高峰，会话短期记忆把内存打满，直接导致用户画像写不进去， Agent 瞬间“失忆”，推荐全乱。后来拆分实例、给短期记忆上 LRU，世界才恢复了清净。

Redis 的内存淘汰策略在记忆场景下的选择，就像管理一台冰箱。冰箱容量有限，每天都要放新的食材。如果规定“满了就不准再放东西”（noeviction），那当天的菜就进不来，全家挨饿。聪明的做法是：容易坏的剩菜（短期记忆）贴上保质期标签，满了就按放了最久没动的原则清理掉（LRU）。而传家宝级别的干货（长期记忆）密封好，放在最深处，绝不轻易扔，但定期看看有没有发霉需要晾晒（归档）。至于冻在底层的大型肉类（向量索引），是压箱底的储备，不能扔，只能换个大冰箱（扩容）。这样冰箱永远有空间流转，不浪费，也不挨饿。
