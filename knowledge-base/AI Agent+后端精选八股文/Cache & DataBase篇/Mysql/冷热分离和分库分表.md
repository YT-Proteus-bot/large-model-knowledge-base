## 题2：进阶题：分库分表后跨分片查询和分布式事务如何处理？

**难度级别**：⭐⭐⭐⭐（路由聚合、Broadcast 表、分片键选择、XA/TCC/最终一致性）

**1️⃣ Common Answer**

跨分片查询就是把每个分片都查一遍再合并，性能会比较差。分布式事务可以用 XA 或者 TCC，不过一般都避免跨分片事务，把相关数据放在同一个分片里。

**2️⃣ Impressive Answer**

这是分库分表后的**两大核心挑战**，需要从架构层面系统设计：

**一、跨分片查询处理**

1. **查询路由策略**
- 分片键查询：直接路由到单分片（最高效）
- 非分片键查询：Broadcast（广播到所有分片）→ 内存聚合
- 全局表：小表（如配置表）复制到所有分片，避免跨分片 JOIN
1. **聚合场景方案**
- 分页：LIMIT offset, size → 各分片取前 size 条，汇总后排序再取 size 条
- 排序：类似分页，需全局排序
- COUNT/SUM：各分片聚合结果再累加
- 性能瓶颈：offset 越大越慢，建议用游标分页或限制最大页数

**二、分布式事务方案选型**

## 题4：基础题：分片键如何选择？数据倾斜（热点分片）怎么解决？

**难度级别**：⭐⭐（分片键选择原则、数据均匀分布、热点Key处理、一致性Hash）

**1️⃣ Common Answer**

分片键要选一个能均匀分布的字段，比如用户ID或者订单ID。如果数据倾斜了，就是某个分片数据太多，可能要重新分片或者用一致性Hash。具体怎么选要看业务场景，尽量让数据分散到各个分片上。
