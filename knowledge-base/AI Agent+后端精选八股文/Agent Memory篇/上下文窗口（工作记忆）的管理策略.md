# 上下文窗口（工作记忆）的管理策略

## 题1：如何为 Agent 设计上下文窗口的 token 预算分配策略？

- **核心判断：**预算分配的第一步不是“平均切蛋糕”，而是先识别哪些内容是“不可协商的固定开销”，再把剩余额度按任务阶段的边际收益动态分配。

> 〔图片：原文此处为图片或公式截图，未随文档导出〕

- 分配顺序必须是“先预留，再分区”。 以窗口 W 为上限，先扣除三样东西：输出预留（**不给输出留空间，模型会在生成中途被截断**）、工具 Schema、安全余量。剩余额度才进入输入侧的分区。常见的错误是“历史优先”——让对话历史吃掉剩余额度，结果系统指令和工具定义被挤出，行为完全不可控。
- 剩余输入按功能区划，而不是按消息类型堆叠。 一个可操作的划分是：System 规则与硬约束（保护区，不参与软排序）、当前目标与任务状态、直接证据（**RAG/Tool 中与当前子任务最相关的片段**）、对话历史、低相关候选与日志（**弹性预算，最先被压缩的对象**）。System 规则、硬约束、Checkpoint 和直接证据属于保护区；旧历史、低相关候选和日志竞争弹性预算。
- 预算不应该是一个静态比例，而应该随任务阶段切换。 规划阶段保留目标、约束、可用工具和高层状态；执行阶段突出当前子任务、依赖变量和最近观察；汇总阶段保留结果、证据和未决风险。知识库问答场景 RAG 配额可以大，工具调用密集场景工具返回配额可以大，长对话场景历史配额可以大——配额是场景的函数，不是拍脑袋的常数。
- 预算的目标是“**单位 token 的任务贡献最大化**”，不是把窗口填满。 填充率是一个虚荣指标；真正需要监控的是每一类内容在任务成功中的归因贡献。如果一段历史被保留但没有被任何后续决策使用，它占用的预算就是纯成本。

**面试表达要点：**先预留输出和安全余量，再按“保护区 / 当前状态 / 直接证据 / 弹性历史”分区，最后按任务阶段动态调整权重。预算的判据是边际信息价值，不是填充率。

## 题2：上下文窗口管理有哪些主流策略分类？分别解决容量、质量还是成本问题？组合时如何避免互相抵消？

核心判断：主流策略可以按它们主要作用的问题维度分成四类——容量类、质量类、成本类、结构类。组合的失败往往不是因为策略本身不好，而是因为两个策略在同一个信息上施加了方向相反的操作，或者一个策略的“丢弃”把另一个策略“钉住”的东西扔掉了。

容量类策略直接回答“窗口装不下怎么办”：滑动窗口/截断、递归/分层摘要、检索式记忆（把历史外置到向量库）。它们主要解决容量问题，但各自附带不同的代价：滑动窗口零成本但纯 recency bias，超过 20–30 轮基本失效；摘要保留长程结构但引入摘要损失和复合衰减（summary-of-summary）；检索式记忆可扩展到无限历史，但丢失对话流，turn n-1 不一定是对 turn n 查询最相似的片段。

质量类策略回答“窗口没爆但模型没用好”：优先级截断/重要性分级、重排序与位置编排、去重。优先级截断给消息打重要性分，窗口满时按分数淘汰，而不是按时间淘汰；重排序把关键证据放在靠近生成位置的开头或结尾，缓解 Lost in the Middle。质量类策略通常不节省 token，它们优化的是同一预算下的信息利用率。

成本类策略回答“怎么让单位 token 更便宜”：工具结果裁剪/字段白名单、Prompt 前缀缓存、按需工具 Schema、输出上限。编码 Agent 的历史里 70% 以上往往是工具输出的“尸体”，压工具结果的收益远大于压对话。前缀缓存让稳定前缀只付一次成本。

结构类策略回答“怎么让状态本身可管理”：Todo/结构化状态卡、Checkpoint、阶段摘要。它们不直接压缩，而是把“过程性膨胀”转化为“有界的状态描述”，让上下文不随步数线性增长。

组合时避免互相抵消的三个操作性规则：

第一，不要在同一信息上同时施加“丢弃”和“钉住”。 滑动窗口的淘汰逻辑是 recency-based，而重要性分级的逻辑是“约束类消息无论多旧都保留”。如果滑窗先执行，第 3 轮的硬约束在第 30 轮之前就被扔掉了，重要性分级根本没有机会看到它。正确的顺序是：先由重要性/规则把“不可协商项”提取到固定位置，再对剩余弹性内容执行滑窗或摘要。

第二，摘要的输入必须包含最近 N 轮原文，禁止“摘要的摘要”滚雪球。 递归摘要如果每一轮都在上一轮摘要的基础上再摘要，细节每滚一层衰减一次，滚三轮后错误信息会被永久固化。防止抵消的方式是：每次压缩从原始转录（或包含最近原文的窗口）生成新摘要，而不是从旧摘要生成。

第三，质量类策略的收益会被容量类策略的粗暴截断吃掉。 重排序把关键证据放到末尾附近，但如果紧接着触发一次全量摘要，位置优势就被重新洗牌了。组合时应该让压缩发生在重排序之前，或者在压缩后的装配阶段重新执行位置编排。

面试表达要点：容量类管“装不装得下”，质量类管“用不用得好”，成本类管“贵不贵”，结构类管“乱不乱”。组合的前提是定义清楚操作顺序和不可协商项的提取时机，否则滑窗会先把重要性分级要保护的东西扔掉。

## 题3：滑动窗口、递归摘要、重要性分级如何选型和组合？压缩本身引入信息损失时，用什么信号判断该换策略？

核心判断：三者不是“选一个”的关系，而是分别回答“丢什么”“合什么”“留什么”。选型的依据不是哪个更先进，而是信息的半衰期分布——如果关键信息是低频且长寿命的，滑窗单独用一定会丢；如果信息是高频且短寿命的，摘要的 LLM 调用成本就是浪费。

滑动窗口适合短会话、无状态或弱状态场景，以及作为其他策略的兜底截断。它的优势是零延迟、零 LLM 成本、行为完全确定；缺陷是 recency bias，超过 20–30 轮后长程引用基本失效。当信息半衰期短于窗口覆盖范围时，滑窗是合理选择；当半衰期长于窗口时，滑窗单独用就是结构性失败。

递归/分层摘要适合长会话、需要跨阶段保持叙事连续性的场景。它的优势是保留长程结构、压缩旧内容；代价是 LLM 调用延迟和成本、摘要损失、以及复合衰减的风险。选它的信号是：任务需要理解“之前发生了什么、为什么走到这一步”，而不仅仅是“最近在聊什么”。

重要性分级/优先级截断适合信息价值分布高度不均匀、且存在“低频关键约束”的场景——用户说过一次“金额超过 500 要审批”，这个约束在第 30 轮仍然生效。它的优势是不需要 LLM 调用就能保护关键项；缺陷是重要性判断可能不准，需要规则或人工标注来锚定。

组合的典型形态是分层压缩：近期原文 + 中期摘要 + 远期关键事实/结构化状态。更具体的操作形态是：钉住区（System 规则、硬约束、Checkpoint、未完成事项，无论多旧都保留原文或结构化记录）+ 滑窗/摘要区（中间段的工具返回和过程性讨论，按半衰期压缩）+ 丢弃区（确认类、重复类、寒暄）。

判断“该换策略”的信号，不是压缩率，而是压缩后的行为退化模式：

- 重复提问：模型反复询问已经提供过的信息 → 摘要或滑窗丢掉了关键实体，需要增加钉住区或改用抽取式保留。
- 约束违反：模型违反了用户早期给出的硬约束 → 重要性分级没有把约束类消息提取出来，或者滑窗先于重要性执行。
- 自信的错误（confident blunders）：模型断言了被压缩掉或已被推翻的旧信息，而不是承认“不记得” → 摘要发生了语义漂移，或者摘要吸收了工具调用参数中的过时值，需要从原始转录重建而非在旧摘要上迭代。
- 复合衰减迹象：摘要越滚越模糊，具体信息让位于“技术上正确但操作上无用”的泛化表述 → 必须切换到“从原文重建摘要”的策略。

一个更底层的换策略判据来自信息半衰期：如果某类消息的衰减速度很慢（硬约束、授权状态、未完成承诺），它不应该进入“按位置一刀切”的压缩区，而应该被单独抽出放在固定位置。当同一类信息反复在压缩后丢失时，问题不是“压缩力度不够”，而是策略类型不匹配。

面试表达要点：滑窗管“最近”，摘要管“脉络”，重要性分级管“不可丢的低频项”。换策略的信号是压缩后的行为退化模式——重复提问、约束违反、自信错误、摘要泛化，而不是压缩率的高低。
