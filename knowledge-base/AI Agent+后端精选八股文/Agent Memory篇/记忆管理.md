## 题1：Agent 为什么必须单独设计记忆模块？LLM 本身的无状态性带来了哪些具体问题？

**核心判断：无状态性不是 LLM 的“缺陷”，而是它作为推理引擎的架构前提。记忆模块之所以必须“单独”设计，是因为无状态性把“推理的瞬时性”和“经验的累积性”压在了同一个平面上——而这两件事的存储语义、更新频率和失败模式完全不同，不能靠“把上下文拉长”来合并解决。**

**无状态性的具体问题，可以拆成四个可观察的失败模式：**

- **① 跨会话失忆（cross-session amnesia） 。**每一次推理开始于一个空白的上下文，除非外部记忆机制被显式构建。用户必须在每一次新会话中重新陈述自己的偏好、项目和处境。这不是“偶尔忘事”，而是结构性的：Agent 没有“上次我是谁”的连续感。
- **② 上下文溢出导致的“老年性遗忘” 。**上下文窗口是硬约束，对话历史拉长时最旧的内容被静默截断。Agent 开始与自己的先前推理相矛盾——不是因为它“错了”，而是因为那段推理“旧了”。扩大窗口只是延缓了这个过程，不能取消它：**更长的上下文放大了工作记忆**，但不提供跨会话的持久存储、结构化知识组织和选择性检索。
- **③ 语境失忆与重复交换。**上下文窗口在每个会话后重置，导致“contextual amnesia”——重复的信息交换，以及长期个性化知识的丢失。RAG 可以缓解“查不到”，但不能替代“记不住”：RAG 是“查”，不是“记”。
- **④ 检索信息的认识论同质化。**当用扁平 RAG 把检索到的片段塞进上下文时，所有片段被赋予同等的权威性。一个在某次对话中试探性提取的事实，和一个人工确认过的地面真相，以相同的权重进入 prompt；LLM 无法区分两者，于是推测性记忆跨会话复合成虚构。

**面试表达要点：不要说“LLM 没有记忆所以加一个记忆”**，而要说“**无状态性保证了推理的可扩展性和操作安全性**，但它使经验无法在时间中沉淀；记忆模块的本质是把‘瞬时推理’和‘累积经验’解耦到两个具有不同持久化语义的子系统里”。

## 题2：短期记忆和长期记忆分别应该保存什么？边界怎么划？

**核心判断：**边界不在于“时间长短”或“存不存数据库”，而在于“是否跨会话可复用，且是否经过提炼而非原始堆积”。一个已经持久化到向量库的会话历史，仍然可能只是线程级短期记忆；一个没有落盘的、但在当前推理中被反复使用的约束，如果在未来会话中会被重新召回，它在功能上就已经是长期记忆。

**短期记忆保存的是维持当前连续性所需的状态：**当前目标、当前计划、最近的消息、临时变量、尚未完成的推理中间结果。它的判据是“此刻是否需要它来继续推进任务”。短期记忆的失败模式不是“存不下”，而是“激活失当”——不激活等于失忆，乱激活等于让无关历史淹没当前任务的信噪比。

**长期记忆保存的是可跨会话复用的抽象：**用户偏好、稳定事实、实体关系、项目知识；某类任务“如何完成”的操作流程与策略；以及“某次任务发生了什么、结果如何”的可追溯经历。它的判据不是“这条信息重不重要”，而是“它是否具有超出当前会话的复用价值，并且经过了足够的提炼，值得被未来的任务按需召回”。

**边界的操作性定义可以压成一句话：**日志保存证据，短期记忆维持当前连续性，长期记忆保存可复用抽象，规则保存权威约束，Skill 保存经过验证的程序。持久化本身不构成长期记忆；长期记忆需要满足跨会话复用、有明确作用域、经过提炼、有来源与置信度、支持更新与审计、能按需召回。

**面试表达要点：**边界不是“会话开始/结束”这条线，而是“复用半径”这条线。短期记忆回答“这一轮接下来怎么做”，长期记忆回答“下一次遇到同类情境时，什么应该被预先知道”。

## 题3：你了解哪些记忆分类框架？CoALA 的四类记忆分别对应 Agent 系统中的什么？

**核心判断：**CoALA 的价值不在于“四个名词”，而在于它把 Agent 记忆从“对话历史”的狭义理解，扩展成了覆盖“经历、事实、技能、当前状态”的广义认知架构。更关键的是，它和今天工程实践中已经自然分化出来的 Skill、RAG/知识库、Session 历史形成了可映射的关系。

CoALA 的深刻之处在于它的映射“踩中了演进路线”：程序记忆对应今天卷的 Skill；语义记忆对应 RAG 和知识库；情景记忆对应早期执着的 Session 历史对白。

**面试表达要点：**不要只背四类名字，要展示“CoALA 不是学术造词，而是把 Agent 系统中已经自然分化出来的存储形态（上下文、Session 日志、知识库、Skill）提升成了一个有认知科学根基的分类坐标系”。

## 题4：工作记忆、会话记忆、长期记忆三层之间，信息是如何“晋升”和“回注”的？

**核心判断：**晋升不是“把会话复制进向量库”，而是一套受控的“记忆编译”过程；回注也不是“把检索结果塞进 prompt”，而是带作用域、带置信度、带冲突处理的按需激活。两端的核心工程问题都不是“存/取”，而是“判据”。

晋升的方向（短期 → 长期） 大致是一条受控管线：

会话事件 → 候选记忆提取 → 类型识别（情景/语义/程序）→ 作用域判断 → 价值评分 → 证据校验 → 去重与冲突处理 → 持久化 → 建立索引

关键触发信号包括：重复/复现——孤立的单次经历停留在瞬态存储中，只有重复出现的模式才驱动向稳定长期记忆的巩固；惊讶度——预测误差大的事件更可能被标记为值得晋升；任务完成/阶段收束——会话结束时对阶段摘要和可复用结论做一次巩固；周期性离线巩固——双缓冲巩固中，新记忆先进入“热缓冲区”观察，通过质量检查（复核、去重）后再晋升到长期存储。

回注的方向（长期 → 工作记忆） 不是一次性批量加载，而是按当前任务需要做分层、分域的召回。回注时至少需要携带三样东西才能避免“检索即噪声”：来源与置信度（这条记忆是亲历的、推断的还是权威声明的）、时间语义（它是否已经过期或被覆盖）、作用域匹配（它属于当前用户/项目/组织吗）。回注的失败模式不是“没召回”，而是召回了一堆语义相似但权威等级不同、时效已过的旧记录，把上下文淹成垃圾场。

还有一个容易被忽略的环节：回注会反过来改变长期记忆。当过去经历被召回并重新进入活跃推理时，它会与新经验一起经历后续巩固，被强化、补充或修正。这意味着“回注”不是单向读取，而是记忆生命周期的一部分。

**面试表达要点：**晋升的判据是“复用价值 + 证据质量 + 重复证据”，不是“存了没有”；回注的判据是“作用域匹配 + 置信度分层 + 时效有效”，不是“相似度高就塞进去”。

## 题5：静态长期记忆和动态长期记忆为什么要分开？混在一起会怎样？

**核心判断：**静态长期记忆和动态长期记忆的差别，本质上是“参数化存储”和“非参数化存储”的差别——它们的更新成本、可审计性、失败模式和生命周期完全不同。混在一起的后果不是“不够优雅”，而是产生两类无法同时满足的工程约束：你需要动态记忆的可修改性，却污染了静态记忆的稳定性；你需要静态记忆的权威性，却把它拖进了频繁更新的噪声里。

静态长期记忆通常指参数化记忆：固化在模型权重中（预训练知识、微调注入的技能/偏好），读取极快，但难以修改、难以定向删除、难以审计，且静态截止于训练结束的那一刻。它擅长无缝的知识整合，但在靶向删除和审计上失败。
