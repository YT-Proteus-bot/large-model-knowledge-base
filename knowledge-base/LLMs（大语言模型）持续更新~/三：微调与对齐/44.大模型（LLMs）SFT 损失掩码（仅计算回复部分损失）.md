# 44.大模型（LLMs）SFT 损失掩码（仅计算回复部分损失）

> 主题：LLMs（大语言模型）持续更新~ › 三：微调与对齐　｜　原始文件：LLMs（大语言模型）持续更新~/三：微调与对齐/44.大模型（LLMs）SFT 损失掩码（仅计算回复部分损失）.md

## 题1：在 SFT 中为什么通常只对“assistant”部分计算交叉熵损失？写出损失掩码的实现逻辑。

指令微调（SFT）的唯一目标，是让模型学会如何生成高质量的回复。我们只对“assistant”部分计算损失，原因如下：

1. 明确优化目标，避免目标错乱：语言模型的训练目标是“给定上文，预测下一个词”。如果对所有角色（system, user, assistant）都计算损失，模型会被迫同时学习“如何提问”、“如何设定规则”和“如何回答”。这会导致模型在推理时无法确定自己的角色，可能不回答用户问题，而是去续写用户的提问。
1. 只学习有用行为：system prompt 是开发者预先设定的，user 输入是用户给的，都不需要模型去学习生成。如果对它们也计算损失，模型就会浪费大量参数去记忆和复现这些“固定”或“多变”的输入模式，而不是去优化生成回复的质量。
1. 防止有害模仿：如果对 user 输入也计算损失，模型可能会学会模仿用户的攻击性、偏见或恶意提问。这在安全上是不允许的。

损失掩码实现逻辑：

损失掩码是控制哪些位置的输出参与梯度计算的核心机制。在自回归语言模型中，输入序列和目标序列是错位对齐的：输入是 tokens[0:T-1]，目标是 tokens[1:T]。通过构造一个与目标序列等长的掩码向量，将不需要计算损失的位置标记为特殊值（在PyTorch中通常是 -100），损失函数会自动忽略这些位置。

关键点是：掩码必须作用于目标序列（即模型预测的标签），而不是输入序列。掩码与目标序列在维度上严格对齐。

## 题2：如果对话数据格式为 [User] ... [Assistant] ...，如何构造 labels 张量实现仅对 assistant 部分计算损失？

以最简单的纯文本格式对话数据为例：

```
[User] 你好，请问... [Assistant] 您好！很高兴为您服务...
```

构造步骤：

1. 确定目标序列与掩码的对应关系：目标序列长度 = 输入序列总长度 - 1（每个位置预测下一个词）。因此，掩码长度 = len(input_ids) - 1。
1. 找到所有“非Assistant”部分的 token 位置：定位到[User]、[System]这些特殊标记，以及它们后面的所有内容，直到下一个角色的特殊标记开始为止。这些位置对应的所有 token 都是需要被掩盖的。
1. 创建与 input_ids 等长的数组：遍历整个 input_ids，根据每个 token 所属的角色段，在数组的对应位置上标记该 token 是否参与损失计算。对于 assistant 部分的 token，设为原始 token ID；对于非 assistant 部分，设为 -100。

具体示例：

假设对话为："[User] 你好 [Assistant] 我很好"

经过 tokenization 后得到 input_ids = [101, 102, 103, 104, 105]。

标签序列（labels）长度 = len(input_ids) = 5。

由于 "[User] 你好" 是用户部分，不需要计算损失，所以 labels 的前 3 个位置设为 -100。

"[Assistant] 我很好" 是助手回复，需要计算损失，所以 labels 的后 2 个位置保持为原始 token ID。

最终 labels = [-100, -100, -100, 104, 105]。

## 题3：在 HuggingFace 的 transformers 中，如何利用 -100 忽略某些位置的损失？具体写出代码片段。

在 HuggingFace 的 transformers 库中，所有模型的损失函数都遵循 PyTorch 的约定：当 labels 中的某个值为 -100 时，该位置的损失贡献为零。这是内置的、自动处理的行为。

```
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf")
messages = [
    {"role": "system", "content": "你是一个有用的助手。"},
    {"role": "user", "content": "你好，请问..."},
    {"role": "assistant", "content": "您好！很高兴为您服务..."}
]

# 1. 使用 chat_template 格式化对话
input_text = tokenizer.apply_chat_template(messages, tokenize=False)

# 2. Tokenize 整个序列，返回 PyTorch 张量
inputs = tokenizer(input_text, return_tensors="pt")

# 3. 构建 labels 张量（与 input_ids 形状相同）
labels = inputs["input_ids"].clone()

# 4. 找到 assistant 回复的起始位置（示例中为固定位置，实际开发中需要根据 tokenized 后的序列自动识别）
assistant_start_pos = 10  # 假设从第10个token开始是assistant回复

# 5. 将非 assistant 部分的所有位置的 label 设置为 -100
labels[0, :assistant_start_pos] = -100

# 6. 前向传播，自动计算损失（只对 labels != -100 的位置计算）
outputs = model(input_ids=inputs["input_ids"], labels=labels)
loss = outputs.loss
loss.backward()
```
