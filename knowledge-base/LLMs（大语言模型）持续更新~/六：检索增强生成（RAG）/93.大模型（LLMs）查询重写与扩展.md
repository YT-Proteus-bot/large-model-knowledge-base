# 93.大模型（LLMs）查询重写与扩展

> 主题：LLMs（大语言模型）持续更新~ › 六：检索增强生成（RAG）　｜　原始文件：LLMs（大语言模型）持续更新~/六：检索增强生成（RAG）/93.大模型（LLMs）查询重写与扩展.md

## 题1：为什么在 RAG 中需要对用户原始查询进行重写或扩展？

在 RAG 系统中，用户的原始查询通常不是检索的最优形式，直接使用它进行检索往往会导致效果不佳。查询重写与扩展的核心目的，就是弥合用户信息需求的表达方式与文档库中相关内容的表述方式之间的鸿沟，从而提升检索的召回率和精确率。

具体原因包括以下几个方面：

信息缺失与模糊性：用户在提问时，尤其是在对话或多轮交互中，常常会使用省略、指代或依赖上下文背景。例如，用户先问“张三多大了？”，接着问“那他住哪？”。第二个查询如果直接检索“那他住哪”，几乎不可能找到任何有效文档。重写的任务就是将其还原为“张三的住址”。

词汇与语义鸿沟：用户的用词习惯和文档作者往往不同。用户可能用口语化、非专业的表述，而文档是正式的书面语。例如，用户搜索“怎么让自己更开心”，而相关文档的标题可能是“提升个人幸福感的方法”。如果只靠字面匹配的稀疏检索，这个查询就会漏掉这篇文档。重写可以引入同义词、近义词、上下位词，或者用生成模型直接生成更贴近文档措辞的查询版本。

查询的粒度与意图不匹配：用户输入的查询可能过于简短宽泛（如“人工智能”），也可能过于冗长复杂（如一段包含多个子问题的描述）。重写可以根据检索系统的特性，将宽泛查询具体化，或将复杂查询分解为多个独立的具体查询，再分别检索。

多模态与元数据需求：有时用户查询中隐含了对文档类型、时间、来源的需求。例如，用户说“给我看看最新的官方政策”，虽然没有直接说“2024年 白皮书”，但通过重写可以显式地加上时间过滤和文档类型偏好。

因此，查询重写与扩展是 RAG 系统中连接“用户真实意图”与“系统可检索表达”的关键桥梁，它直接决定了检索结果的相关性和最终答案的质量。

## 题2：查询重写的常见方法有哪些？列举至少三种（基于规则、基于同义词、基于生成模型）。

查询重写的方法从简单到复杂，可以根据场景和资源选择。常见的三种方法为：

1. 基于规则的方法：

这是最快速、成本最低的重写方式。它不涉及任何机器学习模型，仅依靠预定义的规则或模板对查询进行变换。

- 同义词替换：通过维护一个领域同义词表，将查询中的关键词替换为它的同义词或标准化形式。例如，将“血压高”替换为“高血压”。此方法简单高效，但需要人工构建和维护词表，无法处理复杂的语义改写。
- 拼写纠错与规范化：修复常见的用户拼写错误，统一大小写、全半角、日期和数字格式。
- 模板填充：对于特定业务场景（如客服、订单查询），使用固定的重写模板，将用户查询中的实体提取出来，填充到结构化的查询模板中。
- 停用词移除与关键词提取：去除查询中无信息量的功能性词汇，保留核心关键词。
1. 基于同义词或知识图谱的方法：

这类方法利用外部词汇资源或知识图谱来扩展查询，比简单同义词表更丰富。

- 基于 WordNet：对于英文，可以利用 WordNet 查找查询词的同义词集、上位词、下位词，将其作为查询扩展词。
- 基于知识图谱：对于包含实体的查询，可以链接到知识图谱（如 Wikidata、企业知识图谱），找到该实体的别名、相关实体、属性。例如，查询“苹果 CEO”，可以通过图谱扩展出“蒂姆·库克”、“Apple Inc.”。
- 基于词嵌入的扩展：使用预训练的词嵌入模型（如 Word2Vec, GloVe）找到与查询词最相似的 K 个词进行扩展。这能捕捉语义层面的相似性，但可能引入噪音，需要结合语境。
1. 基于生成模型的方法（最先进）：

利用强大的 LLM 来自动完成查询重写，是目前最主流、效果最好的方法。它通过精心设计的 Prompt，让 LLM 理解对话历史、用户意图，并生成多个独立、完整、适用于检索的查询。

- 少样本提示：在提示中给出一两个查询重写的例子，然后要求 LLM 对当前查询进行重写。
- 零样本指令：直接向 LLM 下达清晰的指令，例如：“你是一个查询改写助手。请将用户的对话查询改写为一个独立的、简洁的、用于搜索引擎检索的查询。如果用户有对话历史，请根据历史消解指代。”
- 生成多个改写版本：可以让 LLM 生成多个语义相同但表述不同的查询版本，然后并发检索，合并结果，以最大化召回率。

这三种方法并非互斥，而是可以在一个系统中组合使用。例如，先通过规则进行基础的实体识别和纠错，再通过 LLM 进行深层的语义改写和对话消解。

## 题3：如何利用 LLM 对查询进行重写以更好地匹配文档的表述方式？写出提示词思路。

利用 LLM 进行查询重写的核心是构建一个清晰、结构化的提示词（Prompt），为模型设定角色、任务、上下文、约束和输出格式。以下是设计思路和示例。

设计思路：

1. 角色设定：明确告诉 LLM 它是谁。例如：“你是一个专业的查询改写助手，负责为搜索引擎生成最佳的查询词。”
1. 任务描述：清晰地定义它需要做什么。核心是将用户口语化的、依赖上下文的问题，改写成一个独立、精准、关键词丰富的检索查询。
1. 上下文提供：提供可用的多轮对话历史，让 LLM 能够理解指代和省略。
1. 改写原则与约束：
- 自包含：改写后的查询必须脱离对话历史也能独立理解。
- 提取核心实体与意图：将对话中提到的关键实体（人名、地名、专有名词）显式地补充进去。
- 文档化表述：使用更正式、更贴近书面文档的关键词，而非口语词。
- 去除噪音：去除礼貌用语、语气词等对检索无用的成分。
- 简洁性：查询不宜过长，保留对检索最有用的信息。
1. 输出格式：可以要求输出一个或多个改写版本，并使用特定的标记分隔。

提示词示例（用于多轮对话）：

```
你是一个专业的查询改写助手。你的任务是根据用户的对话历史，将用户当前的问题改写为一个或两个独立、简洁的搜索引擎查询。
[对话历史]
用户：你知道张三吗？
助手：张三是一位著名的计算机科学家。
用户：那他今年多大了？
[改写原则]
1. 将省略和指代替换为具体实体（如人名、地名）。
2. 使用适合文档检索的关键词和正式表述。
3. 改写后的查询必须脱离对话历史也能独立理解。
4. 只输出改写后的查询，不要解释。
[输出格式]
改写查询1：...
改写查询2：... (可选)
```
