# 68.大模型（LLMs）PagedAttention

> 主题：LLMs（大语言模型）持续更新~ › 四：推理优化与部署　｜　原始文件：LLMs（大语言模型）持续更新~/四：推理优化与部署/68.大模型（LLMs）PagedAttention.md

## 题1：PagedAttention 是如何借鉴操作系统分页思想来管理 KV Cache 的？

PagedAttention 将操作系统的虚拟内存分页机制引入到 LLM 推理的 KV Cache 管理中。其核心类比是：

- 虚拟地址空间 → 逻辑 KV 序列（每个请求的 token 序列）
- 物理内存 → GPU 显存（存储所有请求的 K、V 张量）
- 页（Page） → 固定大小的 KV 块（如每个块包含 16 个 token 的 K 和 V）
- 页表（Page Table） → 块表（Block Table），记录逻辑块到物理块的映射关系

传统方法为每个请求预分配一段最大长度的连续显存，就像早期操作系统为进程分配连续物理内存，极易产生内部碎片（未使用的预留空间）和外部碎片（释放后的不连续空洞），导致显存利用率低下，无法支持高并发。

PagedAttention 借鉴分页思想，将 KV Cache 划分为大量固定大小的小块，需要时按需分配，不使用时释放回收，实现了：

- 按需分配，动态增长：无需预分配最大长度，只需随着 token 生成逐步申请物理块，显存利用率大幅提高，接近物理极限。
- 无外部碎片：任何空闲块均可分配给任何请求，回收后又能立即用于其他请求，消除了外部碎片。
- 内存共享：多个请求可以共享相同的物理块（如相同前缀的 prompt 或 beam search 的公共部分），只需在各自块表中指向同一物理块，配合写时复制（COW）或引用计数，进一步节省显存。
- 弹性调度：连续批处理可以随时加入新请求或换出老请求，块级别的释放与分配保证了系统的动态弹性。

因此，PagedAttention 实现了接近零浪费的显存管理，使 LLM 推理服务能够支持更大的 batch 和更长的序列，是 vLLM 等系统吞吐飞跃的关键。

## 题2：在 PagedAttention 中，KV Cache 被划分为固定大小的“块”（block），请描述块的分配与映射过程。

物理块：在 GPU 显存中预先分配一个大块内存池，将其均匀切分为固定大小的物理块。例如，块大小 block_size = 16 个 token，则每个块存储某个注意力头（或所有头）的 16 个 token 的 K 或 V 张量。对于所有层和所有头，通常会统筹管理，但逻辑上可以按层/头独立分配。

分配过程（以请求生成为例）：

1. 请求初始化（Prefill 阶段）
- 当新请求到达，系统根据其 prompt 长度估算需要的物理块数量：num_blocks = ceil(prompt_length / block_size)。
- 从空闲块池中分配 num_blocks 个物理块，分配给该请求的 KV Cache。这些物理块在显存中可能不连续。
- 建立一个块表（Block Table），长度为最大可能的逻辑块数，记录了逻辑块索引到物理块索引的映射。
- 在 prefill 过程中，随着 prompt token 被处理，生成的 K 和 V 按顺序写入这些物理块。第一个逻辑块写入 token 0..15，第二个写入 16..31，依此类推，最后一个块可能未填满（存在少量内部碎片）。
1. Decode 阶段动态追加
- 每生成一个新 token，序列长度增加 1。如果当前最后一个物理块已满（即已存储 block_size 个 token），则从空闲池再分配一个新的物理块，并将其索引追加到该请求的块表末尾。
- 新 token 的 K、V 写入这个新块的起始位置（偏移 0）。后续 token 继续填充该块，直至再次满并分配下一块。
1. 映射关系
- 逻辑序列位置 pos（从 0 开始的 token 索引）对应的逻辑块号为 block_id = pos // block_size，块内偏移为 pos % block_size。
- 通过块表查得物理块号 physical_block = block_table[block_id]，则该 token 的 K、V 数据位于该物理块内存区域的偏移 offset * head_dim 处。
1. 释放
- 请求完成或被抢占时，其所有物理块被标记为空闲，回收到空闲池，块表销毁。

这种按块动态分配与映射的机制，完全消除了预分配连续长序列的必要性。
