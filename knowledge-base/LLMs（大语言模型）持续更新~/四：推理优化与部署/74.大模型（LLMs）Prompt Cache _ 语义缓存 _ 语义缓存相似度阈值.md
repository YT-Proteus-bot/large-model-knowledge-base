## 题1：什么是 Prompt Cache？为什么要在 LLM 服务中使用它？

Prompt Cache 是一种用于大语言模型推理服务的缓存机制，通过存储和复用之前处理过的提示（prompt）或其中间计算结果，来避免重复计算，从而降低推理延迟、减少计算成本并提高系统吞吐。

在 LLM 服务中，客户端发送的 prompt 往往存在大量重复或相似的部分：

- 多个请求可能共享相同的系统提示（system prompt），如“你是一个有帮助的助手”。
- 同一用户在多轮对话中，历史消息不断累积，每次新请求都包含完整的对话历史。
- 不同用户可能提出语义相同或高度相似的问题，例如“今天天气怎么样”和“今天天气如何”。

若每次都完整处理这些重复或相似的内容，会浪费 GPU 算力和显存带宽。Prompt Cache 通过缓存 prompt 的某种表征（如 KV Cache、embedding 或完整响应），在后续相同或相似请求到达时直接复用，从而实现：

- 降低首次 token 延迟（TTFT）：跳过已缓存部分的 prefill 计算，显著加快响应。
- 提升吞吐：释放出的算力可服务更多请求。
- 节省成本：减少不必要的计算，降低云服务费用。

Prompt Cache 已成为现代 LLM 推理引擎（如 vLLM、TensorRT-LLM、LangChain 等）的重要优化手段。

## 题2：Prompt Cache 通常缓存什么？是 KV Cache 还是输入 embedding？或是完整响应？

Prompt Cache 可以根据缓存对象的不同分为多个层次：

1. KV Cache 缓存（最常用）

   这是与推理引擎紧密结合的缓存形式。当处理 prompt 时，模型会在每一层为每个 token 生成键（Key）和值（Value）张量，即 KV Cache。如果将某个 prompt 前缀的 KV Cache 保存下来，后续请求若具有相同的前缀，就可以直接复用这些已有的 KV Cache，无需重新计算该前缀的 prefill。

- 优点：与推理内核深度集成，加速效果直接（完全跳过重复计算），且在连续批处理中可弹性共享。
- 代表：vLLM 的自动前缀缓存（Automatic Prefix Caching）、TensorRT-LLM 的 KV Cache 复用。
1. 输入 Embedding 缓存

   对于某些场景，可以缓存 prompt 经过嵌入层（embedding layer）后的向量。但由于 Transformer 的主要计算量在后续层，仅缓存 embedding 的收益较小，较少单独使用。

1. 完整响应缓存（应用层缓存）

   直接缓存 prompt 对应的最终文本输出。当完全相同或语义等价的 prompt 到达时，直接返回已缓存的响应，无需调用模型。

- 优点：零推理成本，延迟极低。
- 缺点：仅适用于确定性输出或允许返回相同答案的场景；需处理语义等价但字符串不同的情况。
- 代表：GPTCache、LangChain 的缓存层。
1. 中间计算结果缓存

   如缓存 prompt 经过某些层后的隐藏状态，但这在实际部署中较少见。

实践中，最重要且普适的是 KV Cache 缓存和完整响应缓存，前者优化在线推理的 prefill 阶段，后者在应用层直接短路模型调用。

## 题3：解释 Exact Prompt Cache：如何通过哈希匹配请求的字符串来命中缓存？

Exact Prompt Cache（精确提示缓存） 是一种基于请求字符串完全相等的缓存策略。当新请求到达时，系统计算其 prompt（通常为完整的原始字符串或关键字段的拼接）的哈希值，并在缓存存储中查找是否已有相同哈希的条目。若命中，则直接返回对应的缓存结果（如完整响应文本或 KV Cache）。

实现流程：

1. 缓存键生成：将请求的 prompt 标准化（如去除尾部空格、统一小写？通常为了精确匹配，不做改变），然后计算哈希（如 SHA256、MD5，或直接使用字符串本身作为键）。
1. 缓存查询：以哈希键查询分布式缓存（如 Redis、Memcached）或本地字典。如果存在且未过期，即为命中。
1. 缓存命中处理：
- 若缓存的是完整响应，直接返回该文本，跳过模型推理。
- 若缓存的是KV Cache，则将对应的 KV 张量加载到推理引擎，与新追加的 token 继续解码，避免重复 prefill。
1. 缓存未命中：正常执行模型推理，并将该 prompt 和结果存入缓存（设置合适的 TTL 和淘汰策略）。

应用场景：

- 系统指令缓存：众多用户共享相同的系统提示（如“你是一个编程助手”），其 KV Cache 可被所有请求复用。
- 重复问答：对于高频标准问题（如“公司地址是什么”），直接返回缓存答案。
- 多轮对话前缀：同一用户的多轮对话，历史消息部分完全重复，可复用其 KV Cache。

优点：实现简单，命中后延迟极低或计算开销为零。

缺点：无法处理语义相同但表述不同的 prompt（如“你好”和“您好”），缓存命中率受限于字符串完全相同。
