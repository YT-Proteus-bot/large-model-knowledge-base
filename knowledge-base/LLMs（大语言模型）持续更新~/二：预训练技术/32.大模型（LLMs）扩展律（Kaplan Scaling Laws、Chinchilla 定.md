### 2. 阐述 Chinchilla 定律的核心结论：给定计算预算，如何分配参数量与 token数。

DeepMind 在 2022 年的论文“Training Compute-Optimal Large Language Models”

（Chinchilla）中对 Kaplan 的结论提出了重大修正。他们通过更严谨的实验（固定计算预算，系统性地搜索模型大小和数据量的最优组合）得出了一套全新的、被广为接受的缩放法则。

Chinchilla 的核心结论：对于给定的固定计算预算，为了最大化模型性能（最小化损失），应该将模型大小（参数量 N）和训练数据量（tokens 数 D）等比缩放。具体来说，模型参数量 N 和训练 token数 D 应该与计算预算 C 满足：

这被称为“Chinchilla 最优点”或“计算最优点”。例如，要训练一个 1B（10 亿）参数的模型，计算最优的数据量大约是 20B（200 亿）token；而对于 10B 模型，需要约 200B token。

核心思想：与 Kaplan 不同，Chinchilla 指出数据量是同等重要的，甚至更重要。许多之前的超大模型（如 GPT-3 175B 仅在约 300B token 上训练）是严重欠训练（Undertrained） 的。它们空有庞大的参数量，却没有足够的数据来充分训练，导致大量计算被浪费。Chinchilla 定律证明了，在相同的计算预算下，使用比 Kaplan 建议更小的模型，但喂给它多得多的数据，可以达到显著更优的性能。

## 题1：3. Kaplan 与 Chinchilla 的结论矛盾在哪里？根本原因是什么？

主要矛盾：两者对“计算最优”时模型规模与数据量的分配比例给出了截然不同的建议。

- 具体比例：根据 Chinchilla，一个 70B 的模型应该在约 1.4T token 上训练；而按照 Kaplan 的公式，同样 1.4T token 的训练量，应该用于一个约 400B 参数的模型。这个分歧巨大，直接决定了价值数亿美元的 GPU 集群的投资方向。

根本原因：

这个矛盾主要源于 Kaplan 等人在进行早期实验时，其分析方法存在系统性缺陷。具体表现为：

1. 对模型大小的定义和分析方法不同：Kaplan 的结论主要基于在固定模型大小下，观察数据和计算量的关系，然后进行外推。他们在分析计算量 C 和模型大小 N 的关系时，使用的是在不同大小模型上训练直至收敛的方法，但为每个模型选择的学习率等超参数并非最优。更重要的是，他们没有在固定计算预算下直接系统性地搜索 N 和 D 的最优组合。
2. 未使用“计算最优”的实验设计：Chinchilla 的关键突破在于其实验方法。他们设定了一系列不同的计算预算（FLOPs 数量），并为每个预算直接进行架构搜索：变化模型大小和训练 token 数，找到使得最终损失最小的那个 (N,D) 组合。这种“直接优化”的方式避免了 Kaplan 方法中的外推误差。
3. 学习率调度的影响：Kaplan 的分析依赖于“早期停止”的训练曲线，而 Chinchilla 则为每个模型训练了足够长的 token 数（使用 cosine decay 调度）。这些细微的实验设置差异，在庞大的外推尺度下被急剧放大，最终导致了根本性的结论差异。

可以说，Chinchilla 通过更严谨、更直接的实验设计，修正了 Kaplan 因实验方法和外推偏差所导致的错误结论，将大模型训练带入了“充分训练”时代。
