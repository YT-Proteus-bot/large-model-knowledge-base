# 长上下文模型

> 主题：Transfomer精选面试 › 七：经典模型与前沿架构　｜　原始文件：Transfomer精选面试/七：经典模型与前沿架构/长上下文模型.md

## 题1：扩展上下文窗口通常需要做哪些模型层面的改动？

扩展上下文窗口不只是增加序列长度，还需解决位置编码失效、注意力计算爆发、训练数据分布偏移等问题。模型层面常需以下改动：

- 位置编码适配或替换：
- 原绝对位置编码（如学习式、正弦）无法外推到未训练长度，需替换为外推友好的相对位置编码（如 RoPE、ALiBi）或对已有位置编码进行插值、缩放。
- RoPE 场景常用位置插值（Position Interpolation, PI）：将测试时的位置索引按比例缩小到训练窗口内；或 NTK-aware 缩放：调高 RoPE 基频，让高频分量旋转变慢以适应更长距离。
- YaRN 进一步结合了 NTK 缩放和温度调优，解决插值导致的相邻 token 区分度下降问题。
- 注意力机制优化：
- 引入高效注意力，如 FlashAttention-2/3，以在长序列上将显存和耗时压到线性或近似线性。
- 采用滑动窗口或稀疏注意力（如 Mistral、Longformer），或混合全局+局部注意力，降低计算量。
- 实现 PagedAttention 或类似的 KV 缓存分页机制，以便在推理时高效管理海量缓存块。
- 训练策略调整：
- 从短序列预训练模型出发，进行长序列继续训练（Continual Pretraining）。需要设计长短混合的数据集，逐步增加序列长度，防止模型遗忘短文本能力。
- 使用分阶段训练或 LongLoRA 等低成本微调方案，只微调部分权重或引入轻量适配器。
- 归一化与稳定性：
- 长序列训练容易出现数值不稳定，需使用更稳定的归一化（如 RMSNorm 预归一化），并采用 bf16 混合精度。
- 有时需要调整优化器（如 Adafactor）或引入 Z-loss 等稳定技巧。
- 并行策略适配：
- 长序列训练显存激增，必须结合张量并行（TP）、序列并行（SP）（如 Megatron-LM 的 SP、DeepSpeed Ulysses），将单序列切分到多卡以分散激活显存。

- YaRN（Yet another RoPE extensioN method）：
- 综合了 NTK 缩放和温度 t。对于长度比 s*s*，先做 NTK 缩放，再对注意力 logits 乘以一个温度系数 1/*t*。这样可以惩罚远距离注意力的分散，更接近训练时的分布。
- 微调结合：YaRN 作者提出训练时使用动态插值（如先不加温度，逐步引入温度），或者在微调中使用 YaRN 配置。实践上，YaRN 可以直接零微调外推到很长的长度（如 128K），但若在长数据上稍作微调，效果更为稳固。微调时依然可使用 YaRN 计算的动态缩放位置。

总结：这三种方法都可在微调时固定下来作为位置编码策略，PI 通常需要较多微调恢复局部性，NTK 和 YaRN 可以少量微调甚至零样本外推。

## 题3：长上下文训练的数据混合策略是什么？如何构造长短混合的数据集？

纯粹的极长文本训练会破坏模型处理短序列的能力，因此需长短混合训练。策略如下：

- 数据分布设计：
- 遵循“短序列保基础，长序列扩展”原则。典型混合比例：约 50%～70% 短序列（原预训练窗口内），30%～50% 长序列（新的目标窗口长度）。
- 长序列数据可以从书籍、代码、学术论文、长对话中获取，确保来源的多样性。
- 部分工作使用 “长序列上采样”：对长文档赋予更高的采样权重，同时维持充足的短样本量。
- 构造方法：
  1. 拼接短文档：将多个短文档用分隔符（如 <|endoftext|>）拼接到目标长度。注意需保留分界 token，并禁止注意力跨越文档边界（使用注意力掩码或文档标识）。
  1. 自然长文档：直接使用长文本，如法律文档、长篇小说、维基百科完整页面等。
  1. 合成数据：用已有的长序列任务（如长程问答、摘要）生成预训练格式的文本。
- 训练调度：
- 分阶段逐步增加序列长度。例如，先在原长度（4K）微调一定步数，然后切换到混合长度（8K→32K→128K），每个阶段逐步提升最长长度。
- 动态 batch 序列长度：在一个 batch 内包含不同长度的序列，通过 packed sequence 方法组合，最小化 padding。实现时可用 Ragged Batch / 变长序列支持。
- 数据标签与模型调整：
- 使用特殊的位置标识（如 token type ids）或直接依赖位置编码，使得模型学习区分长度。
- 若使用 PI 等插值，可只在长序列数据上微调，短序列仍使用原位置编码，或者统一使用插值后位置。
