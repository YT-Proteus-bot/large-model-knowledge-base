### 1. 记忆写入由模型自主还是规则准入？什么条件会把“随口一句”固化成长期事实？

默认“模型提案 + 规则准入 + 高风险确认”，不能让模型自主决定写入。 模型可以识别候选（“这句话可能值得记”），但“能不能落库、以什么状态落库”必须由规则和闸门裁决。

模型自主写入的风险：把推测当事实、把反讽当偏好、把临时情绪当稳定特征、把一次性事件当长期约束、被注入诱导写入恶意内容；写入的“自信”和“正确”脱钩。

“随口一句”被固化的条件：

- 缺少来源/置信/状态标签：一句话没有“用户明确说/模型推测/临时”的区分，写入后一律当事实。
- 没有去重/合并/NOOP：重复出现被当“重要”，或每轮都写。
- 没有时效/条件： “今天不想开会”被写成“用户不喜欢开会”，条件、时间、否定丢失。
- 模型过度抽取：把寒暄、情绪、假设、反讽抽成偏好/事实。
- 写入触发太频繁：每轮/每消息都沉淀，临时内容进入长期库。
- 高风险无确认：身份、权限、偏好改写没有用户确认。

正确结构：规则做硬准入（类型、来源、大小、敏感、高风险确认、去重、NOOP），模型做候选抽取和语义归一；写入带 source/confidence/status/timestamp/valid_until；低置信/推测进“待确认区”，不进“生效区”。

收束：写入由“模型提案 + 规则准入 + 高风险确认”共同决定；随口一句被固化，根因是缺来源/置信/时效/去重/NOOP/确认。模型可以建议记，不能独裁落库。

### 2. 记忆投毒和提示词注入的持久化通道是什么关系？恶意内容多久后被触发？

记忆投毒是提示词注入的“持久化通道”之一：注入让模型把恶意内容写入长期记忆/检索库，之后被无关请求召回触发。 普通注入是单次上下文攻击；记忆投毒是“一次写入、长期潜伏、跨会话触发”。

关系：

- 注入是入口：攻击者通过网页、文档、工具返回、用户输入夹带指令，诱导模型“记住”恶意内容或把它写入记忆。
- 记忆是持久化通道：错误/恶意内容进入长期记忆、知识库、工单、文档，跨会话存活。
- 检索是触发器：之后某个无关请求召回该记忆，模型把它当事实/指令执行；触发时间可能几分钟、几天、几周后，取决于召回条件。
- 自我复制：恶意内容可能诱导模型写入更多记忆/文档，扩散。

触发时间：不固定。取决于写入时机、检索 query 相关性、记忆时效/权重、是否被人工审核；可能很久以后才触发，也可能被高频主题快速召回。存储型注入的危险就在“延迟触发、难归因”。

防御：写入侧安全扫描、来源/信任级别、租户隔离、低信任内容不进指令区、检索侧过滤/标注“不可执行”、执行层权限闸门、审计/撤销。不能因为“在库里”就默认可信。

收束：记忆投毒是提示词注入的持久化通道，注入负责写入、记忆负责潜伏、检索负责触发；触发时间不确定，可能很久后。防御要覆盖写入准入、来源信任、检索过滤和执行闸门，不能只防单次输入。

### 3. 多租户共享向量库，隔离做在写入打标签、检索过滤还是物理分库？哪层漏了会串数据？

三层都要，但硬隔离在写入归属和检索过滤，物理分库按合规/规模选；只做一层会串。

- 写入打标签（归属权威）：每条记忆带 tenant_id、user_id、workspace_id、来源、时间；写入时从认证上下文派生，不信任模型/客户端自填；缓存键也带租户。漏了：数据混存，后续无法区分归属。
- 检索过滤（强制隔离）：查询强制带租户/用户/工作区过滤，先过滤再召回；向量检索/关键词/重排都带过滤；跨租户召回直接拒绝。漏了：即使存储有标签，查询不带过滤仍会召回其他租户内容——这是最常见的串数据来源。
- 物理分库/命名空间（强隔离）：按租户分 collection/库/索引，或合规客户独立部署；适合强合规、大规模、故障隔离。漏了不一定串，但逻辑隔离出错时影响面大。
- 旁路：embedding 缓存、检索缓存、摘要服务、会话缓存都要带租户维度；漏了会在缓存层串数据。
- 审计：跨租户访问告警、归属校验日志。

哪层漏了会串：写入漏 → 数据混存；检索漏 → 查询召回跨租户；缓存漏 → 旁路串；物理隔离漏 → 逻辑 bug 影响面大。 存储和检索是硬隔离，Prompt 层只是最后防线。

收束：多租户隔离要“写入归属 + 检索强制过滤 + 物理/命名空间按需 + 缓存旁路隔离 + 审计”；写入漏混存，检索漏召回串，缓存漏旁路串。只做 Prompt 层等于没隔离。

### 4. 团队共享记忆写入要不要审核？污染扩散速度和审核时效损失怎么权衡？

默认要审核，但按“风险/来源/影响范围”分层：高风险前置审核，中风险自动校验+后审，低风险先写后审+标注。 不审核污染跨人/跨 Agent 扩散且难回滚；全审核拖时效、增成本。

不审核的风险：错误一次写入、多次消费；跨会话自我强化；难归因、难撤销；越权/敏感信息共享；团队责任模糊。

审核的代价：写入延迟、人工成本、流程摩擦；高频低价值写入被阻塞；紧急任务等不起。

分层策略：

- 高风险（写操作规则、合规、金额、权限、跨团队事实）：写入前审核 + 来源/证据 + 双人复核。
- 中风险（团队事实、SOP、偏好）：自动校验（来源、去重、冲突、置信）+ 抽检/后审。
- 低风险（个人草稿、可回滚、临时）：先写后审/自动去重，标注“未审核”。
- 版本化/可撤销：错误可覆盖、可回滚，降低审核压力。
- 紧急通道：临时写入 + 标记未审核 + 后续复核；高风险不例外。

收束：共享记忆默认审核，按风险分层；不审核扩散快、难归因/回滚，全审核拖时效。高风险前置，中风险自动+后审，低风险先写后审+标注，配版本化/可撤销。
