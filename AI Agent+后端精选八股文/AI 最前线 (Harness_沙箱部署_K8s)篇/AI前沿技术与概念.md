#### 1. 长程 Agent 成功率≈pⁿ，级联错误、记忆、状态管理，哪个修复收益最高？

状态管理的修复收益最高，因为它直接改变了级联错误产生的结构条件，而不是在错误发生后去弥补。

长程 Agent 的成功率约等于 pⁿ，核心痛点不在于单步成功率 p 不够高，而在于中间步骤的错误会沿着决策轨迹级联放大。现有的 RAG 或 Agent 记忆系统按语义相似度组织历史，在决策时检索相关内容，但这与执行状态的依赖关系是错配的——它会割裂决策轨迹，并且把有效轨迹和错误轨迹混在一起，导致状态重建不连贯、错误无法隔离。

状态管理（以 MAGE 为代表）的干预点在这里：它把记忆重新组织为层级状态树，Agent 的当前状态由活跃的根到当前节点的路径推导而来，包含子目标摘要、近期轨迹和来自其他分支的提示。关键操作包括 Compress（压缩已完成子目标）、Maintain（校验摘要）、Revise（恢复至目标边界并切换到新分支），这些操作的共同效果是将错误片段从活跃路径中隔离出去，同时限制上下文增长。

量化收益非常显著：在 MemoryArena 上，平均任务成功率提升 7.8–20.4 个百分点，同时 token 消耗降低 55.1%。消融实验进一步拆分了收益来源：仅仅移除 Compress 这一步，就会导致成功率下降 7.3 pp（Web Shopping）/ 6.7 pp（Travel Planning），同时 token 消耗膨胀到完整模型的 2.4 倍 / 1.8 倍；移除 Revise 也带来 4.0–5.2 pp 的下降。这说明级联错误的根源不是“记忆不够多”，而是“错误没有被隔离、状态没有被正确压缩和修订”。单纯增加记忆容量而不改变组织方式，错误会继续在扁平的历史中传播；而状态管理直接从轨迹结构上切断了错误的传播路径。

#### 2. 多 Agent Token 开销 4–15 倍，何时必要隔离，何时更贵级联？

隔离是否值得，取决于“级联损失”是否超过“隔离的固定开销”。 这个判断不能只看 token 单价，要看失败的成本结构。

隔离必要（且划算）的场景：

- 下游动作具有不可逆副作用。如果 Agent B 会基于 Agent A 的输出执行写操作（扣款、发邮件、修改数据库），那么 A 的错误传入 B 的代价远不止 token，而是一次真实的副作用。此时隔离 A 和 B 的上下文、在边界做显式校验，用隔离的额外 token 换取“阻止一次错误写操作”，是明显划算的。
- A 的输出包含敏感数据（PII、权限凭证）。级联传播意味着敏感数据会扩散到更多 Agent 的上下文和日志中，合规和审计成本会以乘法级增长。隔离可以收窄数据的可见范围。
- A 和 B 的任务本质独立，只是共享输入。例如多个 specialist 各自从同一份原始数据出发做分析，彼此之间不需要看到对方的部分结果。此时隔离可以并行执行，并且避免“A 的中间噪声”污染 B 的推理。

级联更贵（隔离不划算）的场景：

- 下游任务的正确性严格依赖上游的完整轨迹。如果 B 需要知道 A 为什么做出某个决定（而不仅仅是最终结论），隔离就需要把 A 的完整推理摘要传过去，这个摘要的生成成本和失真风险可能超过直接让 B 看到 A 的原始输出。
- A 的输出是下游任务的核心输入，且难以结构化压缩。例如 A 生成了一段长文本分析，B 必须基于它继续写作。此时把 A 的输出“隔离”成结构化字段会丢失大量语义，反而需要额外的重建步骤。
- 级联的 token 膨胀主要来自“全量传递”而非“必要传递”。如果 A 把完整对话历史全量推给 B，膨胀的是无关上下文；真正的修复是按下游声明的需求传递，而不是把 A 和 B 彻底隔离开来——隔离和“最小化传递”是两件事，后者往往能以低得多的成本解决膨胀问题。

关键判断标准：隔离的 token 开销是线性的、可预测的；级联的失败成本是指数的、不可预测的。 当级联可能导致副作用、敏感数据扩散或整条轨迹作废时，隔离的固定溢价是值得支付的；当级联只是传递了必要信息、且失败模式是可恢复的，隔离反而在用结构复杂度换取一个并不存在的风险。

#### 3. 投机解码加速由接受率和草稿长决定，为何有最优 draft 尺寸？

因为每增加一个草稿 token，都同时支付“草拟成本”和“验证成本”，而接纳收益只来自被接受的前缀。 这两条曲线相交的位置，就是最优 draft 长度 K。

形式化地，在草稿长度 K、接受率 α、草拟耗时比 ρ（小模型单步耗时 / 大模型单步耗时）下，每轮验证产出的期望 token 数为：

相对单步时间是：

其中分子是每轮的总时间（大模型验证一次 + 小模型草拟 K 次），分母是每轮产出的有效 token 数。最优 K 就是让这个比值最小化的点。

直觉上，K 增大时：

- 接纳收益递减：每多草拟一个 token，它被接受的概率是 αᵏ，指数衰减。K=1 时第二个 token 的接受概率是 α²，K=4 时第五个 token 的接受概率是 α⁵——越长的草稿，新增 token 越难被接受。
- 验证成本线性增长：大模型每轮验证都需要处理 K 个候选位置，K 越大，验证的计算量和 KV 访问量越大。
- 草拟成本线性增长：小模型即使很快，K 次前向也是 K 倍的开销。

在一个典型配置（ρ≈0.1，α≈0.75，K=4）下，相对单步时间约为 0.47，即约 2.1× 加速。如果 K 增加到 8，接纳的期望 token 数只从约 3 增加到约 3.5，但验证和草拟的成本几乎翻倍——边际收益低于边际成本，加速比反而下降。如果 K 减小到 1，虽然每轮成本低，但每轮只能接纳约 0.75 个 token（因为 α<1），验证的固定开销被摊薄得不够，加速比也不如 K=4。最优 K 是“接纳收益的边际递减”追上“成本线性增长”的那个交叉点，它不是由单一变量（接受率或草稿模型大小）决定的，而是 α 和 ρ 共同作用的结果。

#### 4. PD 分离后 Decode 的 KV 从哪来？传输吃掉收益时何种流量仍可部署？

Decode 的 KV 来自 Prefill 节点，通过网络传输过去。 PD 分离的本质分工是：Prefill 节点一次性读入完整输入，为每个输入 token 位置计算并生成 KV cache；Decode 节点没有这段输入序列的 KV cache，因此必须等 Prefill 完成后，将整段输入的 KV cache 经网络从 Prefill 传到 Decode，传输完成前 Decode 无法开始生成。一个 64K token 的输入，单卡对应的 KV cache 体积约为 392–398 MiB，这笔传输的耗时就是 PD 分离的固定开销。

当传输吃掉收益时，以下流量仍可部署 PD 分离：

- 提示词与生成内容比例远离 1:1，且 prefill 和 decode 确实需要不同参数。这是 PD 分离的原始收益来源——两边独立扩缩容。如果传输慢，但只要负载比例足够极端（例如超长提示词、短输出，或短提示词、超长输出），两侧独立调优的收益仍然可能覆盖传输成本。
