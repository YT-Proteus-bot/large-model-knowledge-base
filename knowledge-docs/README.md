## 使用建议

- **直接阅读**：打开对应 md 按目录跳读。根目录 README 的导语里也标了每篇的定位。
- **作为 RAG 语料**：以 `##` 二级标题为切片边界，每个切片保留「文档标题 + 章名」作为上下文前缀。注意两点：一是切片器要能识别代码围栏（围栏内的 `#`、`##` 是注释不是标题，普通按行切分器会误判）；二是每节开头的定义句已经自包含，不需要额外补上下文。
- **作为培训教材**：每篇按「概念 → 原理 → 代码 → 排错」编排，单篇约两周自学节奏；三份技术栈文档（前端、PyTorch、Java）可以并行读。

## 目录约定

- 每篇首部是 YAML front matter：`title` / `topic` / `sub_topic` / `doc_type: kb-doc` / `level` / `chapters` / `chars` / `build_date`。
- 章标题统一为 `## N. 章名`，小节为 `### N.x 小节名`，N 与章号一致，便于按编号定位。
- `_parts/` 是分章写作的中间片段（已加入 .gitignore），仓库里只保留拼装好的成品。

## 维护

片段改动后重新生成：

```bash
python .kb-docs-build/build_docs.py
```

脚本会重新拼装、校验（标题层级、编号连续性、代码围栏配对、字数下限）并刷新本索引。
